# 架构设计：龙小督上下文与记忆四层方案

<!-- status: draft -->

- 设计: context-memory-v1
- 日期: 2026-09-08
- 基线: AgentScope 自研底座 + PostgreSQL 会话持久化（见 `docs/research/agent-framework-correction.md`），7×24 驻留，DM only
- 配套: `memory-options-comparison.md`（记忆层选型）、`data-model.md`、`flows.md`

## 总览

```
┌─ 组织成员（IM DM）──────────────────────────────┐
│  ① 会话管理层  6h 功能性连续 / 跨重启恢复          │
│  ② 滚动压缩    早期消息摘要化 · 近期消息原文       │
│  ③ 账本记忆层  3h 不活跃 → 摘要归档 → .md 账本    │
│  ④ 分层沉降    活跃账本 → 摘要卡 → 冷存           │
└─ Teable（业务事实源，经 Teable skills 查询）────┘
```

## ① 会话管理层

- **现状**：会话已持久化到 PostgreSQL；AgentScope 运行时 7×24 驻留。
- **窗口策略**：用户级 session 在线时持续累积，不做时间切割——「6 小时」是产品层连续性体验目标，不是会话边界。真正的长度控制由②滚动压缩承担。
- **连续性保证**：窗口内所有消息（含工具调用结果）进入同一上下文；省略/指代式输入依赖近期消息原文理解。
- **跨重启恢复**：重启后按「用户 + 最近活跃 session」从 PG 回放窗口内最近消息（上限 = 滚动压缩保留的原文预算），保证功能性连续。

## ② 滚动压缩策略

- **触发条件**：session 上下文 token 超过预算阈值（初始建议 60k tokens，可调）时触发，不随时间自动触发。
- **压缩方式**：将最早的批次消息（如 20% 预算量）替换为滚动摘要；摘要作为「准消息」留在上下文头部；原始消息始终完整保留在 PG，可回查。
- **无感要求**：压缩对用户不可见（不打断对话、不输出压缩提示）；压缩摘要是③账本归档的补充而非替代——滚动摘要服务当前 session 连续性，账本服务跨 session 长周期记忆。

## ③ 账本记忆层（核心）

- **锚点**：`用户 × 督办事项`；批次（batch）是事项的维度信息，存于 frontmatter，非并列锚点。
- **写入管道**（事件驱动）：
  1. 不活跃检测：扫描 PG `last_active_at`，用户 3 小时无消息 → 生成归档任务（阈值可配）；
  2. 摘要归档：轻量模型摘要 agent 消费任务，拉取该用户自上次归档点以来的未归档消息；
  3. 记账：按归属事项写入/更新对应 `.md` 账本（未识别事项的对话进 `misc.md`，后续可升格为正式事项账本）；
  4. 留痕：账本 frontmatter 记录 `source` 指针（会话/消息区间），可回查原文。
- **回顾（混合触发）**：
  1. 激活注入：话题/事项激活时读取对应账本摘要，注入系统上下文；
  2. 信号检索：对话中出现旧事信号（事项名称/编号、「上次/之前/上周说的」等）时主动检索账本并引用；
  3. 任务预载：督办定时任务（通知/催办/每日汇总）执行前自动加载对应事项背景。
- **规范**：目录结构、frontmatter、正文分段规则见 `data-model.md`；流程见 `flows.md`。

## ④ 分层沉降

| 层级 | 对象 | 规则 | 存储 |
|------|------|------|------|
| L1 活跃账本 | 活跃事项的 `matter.md` | 持续 append；每次写入更新 `updated_at` | 工作区文件（热） |
| L2 摘要卡 | 完结/长期未活跃事项 | 事项完结或 90 天未活跃 → 压缩为 `summary card`（关键决定/承诺/结果/待续事宜） | 工作区文件（温） |
| L3 冷存 | 超过 1 年未访问的摘要卡 | 归档到冷存目录（或快照介质），检索命中时按需加载 | 冷存 |

- 沉降不可逆地保留来源指针，任何层级都可回查 PG 原始消息。
- 汇总类任务（每日汇总）读取 L1+L2，不触达 L3 除非用户显式询问历史事项。

## 与周边系统的关系

- **Teable**：业务事实唯一权威源；账本仅存引用键，业务字段一律现场查询。
- **PG**：会话原文 + 归档任务队列 + `last_active_at` 索引，是账本的事实回查层。
- **issue-17 话题管理**：正交。话题管对话分组，本方案管对话沉淀与回忆；话题切换可能触发账本激活注入。
