# 调研笔记：记忆层候选方案（自研 .md 账本 / Graphiti / mem0）

- 日期：2026-09-08
- 调研目的：为「几十人 / 几百事项」规模的 IM 数字员工选择长周期记忆载体
- 硬约束（来自 PM，不可权衡）：① 账本对普通用户黑盒、开发者可服务器直查；② 与「3 小时不活跃 → 轻量模型摘要 → 写入 .md」的事件驱动归档管道契合；③ 不引入与规模不匹配的重型运维

## 候选 A：自研 .md 账本（agent 自有工作区）

- **机制**：龙小督在服务器工作区维护 `memory/users/{user_id}/matters/{matter_id}.md`，frontmatter 记元数据（锚点、批次、状态、更新时间、来源指针），正文按「背景 / 决定 / 承诺 / 待办 / 原文摘录」分段。归档由轻量摘要 agent 写入；回顾由混合触发（注入/信号检索/任务预载）读取。
- **优点**：零新增基础设施；纯文本可 git 化、开发者天然可直查（满足硬约束①②）；schema 完全按「用户×督办事项」锚点定制；与 PG 中的会话记录互补（PG 存原文，账本存提炼）。
- **代价**：无语义/向量检索（靠目录命名 + frontmatter 索引文件，规模内够用）；无关系推理；检索质量依赖命名与索引规范。
- **运维成本**：≈0（随龙小督服务部署，文件即数据）。

## 候选 B：Graphiti（Zep 开源时序知识图谱记忆）

- **机制**：以 episode（对话片段）为输入，LLM 抽取实体/关系写入时序知识图谱（Neo4j / FalkorDB），支持语义+时间混合检索（RRF），擅长「关系随时间演变」的推理（如「承诺何时被更新过」）。
- **优点**：关系推理与多跳查询能力强；时序模型天然契合承诺/决定的版本演变；有开源社区与 Zep 商业版演进路径。
- **代价**：必须引入图数据库及嵌入模型配置，运维组件 +2 起步；记忆以图节点形式存在，开发者「直查」体验从 cat 文件变成跑 Cypher（违背硬约束①的直查直觉，需另做导出）；与「写入 .md 账本」的既定管道不契合，摘要 agent 需改写成 episode 注入；对几十人/几百事项规模属明显过剩。
- **适用信号**：当记忆查询频繁需要多跳关系推理（跨事项、跨人的影响面分析）且规模上千时重新评估。

## 候选 C：mem0（开源记忆层 + 托管平台）

- **机制**：`add/search` API 从消息中抽取记忆条目，默认向量存储（Qdrant 等），mem0g 变体支持图记忆（Neo4j）。可自托管也可用托管平台。
- **优点**：接入快、API 简单；抽取/更新/遗忘策略内置；托管版免运维。
- **代价**：自托管仍需向量库组件 + 抽取 LLM 调用成本；托管版存在数据出域问题（组织 IM 对话内容出域，合规上基本不可行）；记忆条目存于向量库、黑盒化，与「开发者服务器直查」硬约束直接冲突（只能看到条目，看不到逻辑组织）；内置抽取策略按通用对话设计，对「督办事项锚点 + 批次维度」的结构化诉求需要大量定制覆盖。
- **适用信号**：快速原型验证记忆价值时可短期试用；正式环境仅在自托管且补齐审计导出后重新评估。

## 初步结论（最终以方案对比文档评分表为准）

当前规模与硬约束下，自研 .md 账本为推荐基线；Graphiti/mem0 作为规模与关系复杂度增长后的演进选项，触发条件写入对比文档。
