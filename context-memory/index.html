龙小督 · IM 数字员工的场生命周期上下文与记忆体系

短周期对话连续，长周期基于「用户 × 督办事项」被记得

龙小督嵌入 IM 组织架构，与多名成员长期 DM 协作。本方案按 IM + Teable 的真实使用方式重设计上下文窗口与记忆：通用 AI 工作台的窗口策略、压缩策略、记忆方案均不完全适配，这里给出贴合场景的四层架构与有据可依的记忆层选型。

01概览与场景事实

已锁定的场景事实（PM 确认，2026-09-08 讨论），是全部设计的输入。

底座 已确认

AgentScope 框架自研（纠正 issue-17 调研的 OpenClaw 记载），7×24 驻留；会话持久化于 PostgreSQL；本期仅 DM。

规模 已确认

小型：几十名成员 / 几百个督办事项。文件系统 + 命名规范即可满足检索，无需向量库。

使用方式 场生命周期

上线后在一个窗口内持续使用同一 session 聊天；「会话结束」由用户不活跃界定，而非显式关闭。

Teable 定位 业务事实

Teable 是业务事实唯一权威源，经 Teable skills 查询；不充当记忆存储，账本只存引用键。

设计命题：既保证 6 小时内上下文窗口的连续性（省略/指代输入可凭近期对话理解），又保证数周/数月/数年后，龙小督能基于与一个用户、一个事项的背景，在新鲜会话中继续协作。

02四层架构设计

全栈四层：会话管理 → 滚动压缩 → 账本记忆层（核心）→ 分层沉降。详见 designs/context-memory-v1/architecture.md。

┌─ 组织成员（IM DM）──────────────────────────────┐
│ ① 会话管理层  6h 功能性连续 · 跨重启恢复(PG 回放)   │
│ ② 滚动压缩    token>60k → 早期消息摘要化·近期原文   │
│ ③ 账本记忆层  3h 不活跃 → 摘要归档 → .md 账本     │
│ ④ 分层沉降    活跃账本 → 摘要卡 → 冷存          │
└─ Teable（业务事实源，经 Teable skills 查询）────┘

① 会话管理层

「6 小时」是连续性体验目标而非会话边界；session 持续累积，长度控制交给滚动压缩。重启后从 PG 回放窗口内消息恢复。

② 滚动压缩

超预算时最早一批消息替换为滚动摘要（作为上下文头部「准消息」），原文始终保留在 PG 可回查；用户无感、对话不中断。

③ 账本记忆层

事件驱动：3h 不活跃事件 → 轻量模型摘要 agent 拉取未归档对话 → 写入「用户 × 督办事项」.md 账本；回顾采用混合触发。

④ 分层沉降

活跃事项详细账本 → 完结/90 天未活跃压缩为事项摘要卡 → 1 年未访问冷存；任何层级保留来源指针可回查原文。

03记忆层方案对比

三方案按本场景五维度评分（1–5，等权）。硬约束：开发者服务器直查、契合 3h 归档管道、不引入与规模不匹配的重型运维。

结论

推荐A 自研 .md 账本为基线：零新增基础设施、cat 文件即审计（满足硬约束）、与既定 3h 摘要归档管道天然一体，规模内检索成本可控。

演进B Graphiti / C mem0 作为规模演进选项。触发条件（同时满足）：活跃记忆条目 > 5,000 个事项账本或检索 P95 > 2s；且出现明确的跨事项/跨人多跳关系查询需求。复评顺序：先 mem0 自托管 PoC，Graphiti 作为关系推理确需时的候选。

否决项说明：mem0 托管版存在 IM 对话内容数据出域问题，合规上基本不可行；Graphiti/mem0 的记忆均黑盒化于图库/向量库，与「开发者服务器直查」硬约束冲突（需另做导出层）。

04写入 · 回顾 · 沉降

三条核心流程，详见 designs/context-memory-v1/flows.md；数据规范详见 data-model.md。

写入管道（F2，事件驱动归档）

PG last_active_at 扫描 ──▶ 用户 3h 无消息 ──▶ archive_task(幂等, cursor 断点)
    ──▶ 轻量摘要 agent 拉未归档消息 ──┬──▶ 已识别事项: append {matter_id}.md
                                    └──▶ 未识别: _misc.md（候选主题, 可升格）

回顾（F3，混合触发）

  • 激活注入：话题/事项激活时读 INDEX 定位账本，注入「背景 + 待续事宜」摘要；
  • 信号检索：对话出现事项名/编号、「上次/之前」等旧事信号时主动检索并标注「据 N 月 N 日记录」；
  • 任务预载：督办定时任务（通知/催办/每日汇总）执行前自动加载对应事项背景——覆盖 agent 主动发起的会话。

分层沉降（F4）

L1 活跃账本 ──(事项完结 或 90 天未活跃)──▶ L2 事项摘要卡 ──(1 年未访问)──▶ L3 冷存
         热                                     温                              按需加载

16h 窗口内多轮对话，省略式/指代式输入被正确理解（案例 ≥ 90%）
2滚动压缩后近期原文、早期摘要，对话无缝继续

4隔日/隔周新会话提及旧事项，能凭账本回顾并正确引用背景、决定与承诺
5督办定时任务执行前自动预载事项背景
6完结事项自动沉降为摘要卡，冷存事项可检索加载
7方案对比含三方案场景化评分表与明确推荐、对接设计
8开发者服务器直查记忆文件，无需登录额外系统

06决策记录

2026-09-08 PM 确认的 12 项决策，来源：interviews/2026-09-08-context-memory/summary.md。

#决策点结论
1设计范围全栈四层：会话管理 / 窗口策略 / 压缩摘要 / 记忆层
2记忆锚点用户 × 督办事项；批次是事项的维度信息，非并列锚点
3Teable 定位业务事实源（skills 查询），不充当记忆存储
4记忆载体agent 自有空间 .md 账本，或外部插件（必须给出场景化对接对比）
5短周期连续性功能性连续；超窗滚动压缩，对话不中断
6写入管道3h 不活跃事件 → 轻量模型摘要 agent → 写入事项 .md
7回顾触发混合触发：激活注入 / 信号检索 / 任务预载
8长期保留分层沉降：活跃账本 → 摘要卡 → 冷存
9账本可见性普通用户黑盒；开发者服务器直查
10群聊本期不做，仅 DM
11规模几十人 / 几百事项
12路线决策方式吃透场景后输出方案对比（评分 + 推荐 + 对接设计）

07候选方案调研

详见 docs/research/memory-options-research.md。三候选的机制、代价与适用信号摘要：

A 自研 .md 账本

工作区文件 + frontmatter 元数据 + 分段规范；零基础设施、可 git 化、cat 即审计。代价：无语义检索与关系推理（规模内靠 INDEX + grep 够用）。

B Graphiti Zep 开源

时序知识图谱：episode → 实体/关系抽取，语义+时间混合检索，擅长关系演变推理。代价：图库 + 嵌入模型运维，记忆黑盒化需另做导出，规模过剩。

C mem0

add/search 记忆 API，内置抽取/遗忘策略，接入快。代价：自托管仍需向量库；托管版数据出域不合规；向量库黑盒与「开发者直查」冲突；督办锚点结构需大量定制。

洞察：IM 场生命周期意味着「会话结束」由用户不活跃界定——归档触发器以不活跃事件为准（与写入管道一致）；账本可见性诉求天然排斥托管黑盒记忆服务，这是硬约束而非权衡项；督办场景存在 agent 主动发起的第三类上下文，回顾触发必须覆盖主动会话。

08底座事实纠正

详见 docs/research/agent-framework-correction.md。issue-17 调研文档（2026-08-24）记载底座为 OpenClaw；PM 于 2026-09-08 确认为 AgentScope 自研 + PostgreSQL 会话持久化。本工作包全部设计以 AgentScope + PG 为基线；issue-17 旧文档不回改。两层正交：话题管理管「对话在哪发生」，本方案管「对话沉淀到哪、如何被回忆」。
