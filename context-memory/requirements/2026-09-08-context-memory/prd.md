# PRD: 2026-09-08-context-memory

<!-- status: draft -->

## 产品目标

为龙小督（IM 数字员工，AgentScope + PostgreSQL，7×24，DM only）建立适配「场生命周期」使用方式的上下文与记忆体系：短周期（6h）对话连续无感，长周期（周/月/年）基于「用户 × 督办事项」账本接续协作。

## 功能需求

| 功能 | 描述 | 优先级 |
|------|------|--------|
| F-CM01 会话窗口管理 | 基于 PG 现有会话持久化，定义窗口策略与跨重启恢复，保证 6 小时内功能性连续 | P0 |
| F-CM02 滚动压缩 | 会话超长时早期消息滚动摘要压缩、近期消息保持原文，对话不中断 | P0 |
| F-CM03 不活跃事件捕获 | 捕获用户 3 小时无消息事件，生成归档任务（可配置阈值） | P0 |
| F-CM04 摘要归档管道 | 轻量模型摘要 agent 消费归档任务，拉取未归档对话，按规范写入事项 `.md` 账本 | P0 |
| F-CM05 账本记忆层 | `memory/users/{user_id}/matters/{matter_id}.md` 结构 + frontmatter 元数据 + 写入/读取规范；锚点为「用户 × 督办事项」，批次为维度信息 | P0 |
| F-CM06 混合回顾触发 | ①话题/事项激活时注入账本摘要 ②对话中识别旧事信号（名称/编号/「上次、之前」）主动检索 ③督办定时任务执行前预载事项背景 | P0 |
| F-CM07 分层沉降 | 活跃账本 → 完结事项摘要卡 → 冷存归档，检索时按需加载 | P1 |
| F-CM08 记忆层方案对比 | 自研 `.md` 账本 vs Graphiti vs mem0 场景化评分与对接设计，含演进路径 | P0 |
| F-CM09 开发者直查 | 服务器文件系统直查记忆文件；普通用户黑盒 | P0 |
| F-CM10 督办主动会话预载 | agent 主动发起的通知/催办/汇总会话自动挂载对应事项背景（F-CM06③ 的督办特化） | P1 |

## 非功能需求

- 规模适配：几十人 / 几百事项规模下，文件系统 + 命名规范即可满足检索，不引入向量库/图库等重型依赖（方案对比文档论证）。
- 归档异步：摘要归档管道异步执行，不阻塞用户对话；摘要任务失败可重试、可告警。
- 可审计：账本为纯文本 `.md`，可纳入 git 版本管理；写入必须带来源指针（会话/消息引用）。
- 摘要质量：归档摘要是长周期记忆的源头，需有准确性抽检机制（设计阶段定义抽检规则）。
- 合规底线：账本对普通用户不可见；记忆文件访问权限与龙小督服务同域管控。

## 发布标准

- clarify 阶段：requirements.md / user-stories.md / prd.md 经 PM 确认（human_gate）。
- 设计阶段：方案对比文档 + 四层设计文档 + data-model + flows 经 PM 确认（human_gate）。
- 实现阶段（本次范围外）：F-CM01~F-CM06、F-CM08、F-CM09 验收用例全部通过。

## 风险

- 摘要质量风险：轻量模型摘要可能遗漏或曲解承诺类信息；缓解：账本 schema 强制「承诺/决定」段、人工抽检、来源指针可回查原始消息。
- 底座事实冲突：issue-17 调研文档记载 OpenClaw，本方案按 PM 确认改为 AgentScope；缓解：`context-memory/docs/research/agent-framework-correction.md` 记录该决策，设计文档以 AgentScope + PG 为准。
- 记忆膨胀：账本长期增长；缓解：分层沉降 + 完结事项摘要卡 + 冷存。
- 外部方案绑定风险：若 PM 在 human_gate 否掉方案对比推荐结论，按反馈重出对比，不直接跳设计细节。
