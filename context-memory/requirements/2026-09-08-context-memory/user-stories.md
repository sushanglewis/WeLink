# 用户故事: 2026-09-08-context-memory

## 用户故事一：短周期对话连续

- 作为：组织成员（DM 用户）
- 我希望：在 6 小时内与龙小督持续对话时，即便我的输入很省略（「就按上次那个来」「他回复了吗」），龙小督也能凭近期上下文明白我的意思
- 以便：我像跟同事聊天一样自然地协作，不用每句话都重复交代背景
- 验收标准：6 小时窗口内多轮对话中，省略式/指代式输入被正确理解的案例 ≥ 90%；对话中途无感触发滚动压缩后连续性不中断

## 用户故事二：长周期被「记得」

- 作为：组织成员（DM 用户）
- 我希望：隔几天或几周再聊起同一个督办事项时，龙小督记得我们当时的讨论、我答应的事、做过的决定
- 以便：协作可以接续推进，而不是每次从头解释
- 验收标准：用户 3 小时不活跃后对话自动归档进事项账本；新会话提及旧事项时，龙小督能正确引用账本中的背景、决定与承诺（验收用例：隔日回顾、隔周回顾）

## 用户故事三：龙小督主动会话不「失忆」

- 作为：PM/管理员
- 我希望：龙小督执行督办定时任务（主动通知、催办、每日汇总）时，自动加载对应「用户 × 事项」的账本背景
- 以便：催办口径与当时协作上下文一致，不出现「忘了自己催过什么」的情况
- 验收标准：定时任务执行前自动预载对应事项账本摘要；同一事项的多次催办能在账本中留痕且互相可见

## 用户故事四：业务事实归业务事实，记忆归记忆

- 作为：PM/管理员
- 我希望：督办台账、批次、进度等业务事实仍由 Teable 承载，龙小督通过 Teable skills 查询；账本只记「对话中产生的协作背景」（承诺、偏好、决定、语境）
- 以便：两类信息各自有清晰的权威来源，不互相污染，账本不会因业务数据变化而过期
- 验收标准：账本 schema 中不冗余存储可从 Teable 查询到的业务字段，仅保留引用键（事项 ID、批次）

## 用户故事五：开发者可审计

- 作为：开发者/运维
- 我希望：能在服务器上按目录规范直查龙小督的记忆文件（`.md` 账本、摘要卡），普通用户不可见
- 以便：当龙小督的行为异常时，我能审计「它记住了什么、为什么这么做」
- 验收标准：`memory/users/{user_id}/matters/{matter_id}.md` 目录结构落地；开发者无需额外系统即可直查；用户侧无任何账本暴露入口

## 用户故事六：记忆层技术路线有据可依

- 作为：人类 PM
- 我希望：记忆层技术路线（自研 `.md` 账本 vs Graphiti vs mem0）有基于本场景的正式对比（评分表 + 推荐 + 对接设计）
- 以便：选型决策可追溯，规模增长后的演进路径清晰
- 验收标准：对比文档含三方案在场景契合度、基础设施/运维成本、AgentScope+PG 集成难度、可审计性、规模演进空间五个维度的评分；结论含明确的演进选项（何时应重新考虑外部方案）
