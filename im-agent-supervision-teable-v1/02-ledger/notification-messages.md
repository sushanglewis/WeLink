# 龙小督消息通知文案（场景 × 触发 × 收件人 × 变量）

> 龙小督 IM 消息通知文案的唯一口径（版本记录见 §8；当前 v1.1-draft，在 v1.0-final（2026-09-18 PM 定稿）基础上新增 §7 消息聚合与频控总规则：文案模板与全部单事项文案不变，催促类与提交回执类由「每事项 1 条」改为按「收件人 × 批次」聚合，全局日预算取代单场景顺延）。v1.0-final 口径：文案为可直接开发的最终模板——来源与操作以自然语句内嵌，不做变量拼接；单事项消息随附事项详情，经办人新增场景最多列 3 条。逐条映射到状态机迁移（见 `state-machine.md` §3/§4）与 PRD 需求（AGT-xx，见 `../01-prd/requirements.md`）。既有口径不变：逐级通知不跨级（D-29/AGT-12）、提交即审核、风险/逾期仅通知督办人且不进台账（D-37/D-44）。

## 1. 适用范围与文案规范

- **渠道**：均为龙小督 DM 消息（聊内触达），填报动作统一指向「右侧台账面板」。
- **可直接开发**：每条文案为最终模板，研发按 `{变量}` 替换即可渲染，无需再组织语句；除变量外措辞**逐字固定**，不得即兴改写。
- **占位变量**：统一写作 `{xxx}`，变量字典见 §2；多事项列表中的 `{事项编号N}`/`{交办内容N}` 按序替换，第 4 条起不渲染。
- **轻量规范（相对最初口头模板的修订）**：
  1. 所有文案以「谢谢。」收尾（「DDL 到达」原模板缺结尾礼貌语，已补齐）；
  2. `excel` 统一写作 `Excel`；
  3. 按 09-18 要求内嵌来源人姓名与事项详情，措辞自然化为最终句式。

## 2. 变量字典

| 变量 | 含义 | 格式 / 取值示例 |
|------|------|----------------|
| `{姓名}` | 收件人姓名（当前通知对象） | 真实姓名，如「詹少鹏」 |
| `{来源姓名}` | 来源人姓名（将该事项送到当前节点的经办人/转办人/督办人） | 真实姓名，如「王督办」；催促消息中取该事项原始下发/转办人 |
| `{提交人姓名}` | 实际提交人姓名 | 真实姓名，如「李良龙」 |
| `{事项数量}` | 涉及待办/督办事项条数 | 正整数，如「3」 |
| `{日期}` | 批次反馈截止时间（批次 DDL） | `YYYY-MM-DD HH:mm`（如「2026-09-05 10:00」）；仅日期精度时 `YYYY-MM-DD` |
| `{批次编号}` | 督办批次编号 | `SUP-YYYYMMDD-NN`，如「SUP-20260903-03」 |
| `{事项编号}` | 督办事项编号（即任务编号，统一沿用台账用词「事项编号」） | 如「SJ2608261503」 |
| `{交办内容}` | 事项交办内容 | 主表事项内容字段，消息内全量展示，不截断、不限字数 |
| `{落实情况}` / `{困难问题}` / `{下一步计划}` | **上一次**填报的三要素反馈 | 上轮跟进记录对应字段；**首次督办无上次反馈时渲染「（首次督办，暂无上次反馈）」** |
| `{已填报数量}` | 批次内已提交事项条数 | 正整数；§4.3 已使用，v1.1 补录字典 |
| `{批次事项总数}` | 批次内事项总数 | 正整数（§7.3 滚动合并回执） |
| `{临期数量}` | 批次内临近填报时限未填报事项条数 | 正整数（§7.2 聚合摘要） |
| `{逾期数量}` | 批次内超过填报时限未填报事项条数 | 正整数（§7.2 聚合摘要） |
| `{逾期天数}` | 事项连续未填报天数 | 正整数，如「3」（§7.5 连续逾期） |
| `{新增已提交数量}` | 本批次自上次合并回执以来新增已提交条数 | 正整数（§7.3 滚动合并回执） |
| `{批次数量}` | 摘要涉及批次个数 | 正整数（§7.4 今日督办摘要） |

## 6. 通知通用规则

- **来源表述（自然语句内嵌，不做变量拼接）**：消息以自然句式写明该事项「从谁来、怎么操作而来」——督办下发=「督办人`{来源姓名}`向你交办了…」；转办=「经办人/转办人`{来源姓名}`将…转办给你」；提交=「`{提交人姓名}`已提交…」。催促消息沿用该事项的到达方式措辞（§3.3 措辞 A/B）。批次级、督办人本人触发的消息（导入 §4.1、DDL 到达 §4.3、督办人催促跟进 §4.2）不涉及他人来源，措辞自带。
- **单事项消息随附事项详情（09-18 PM 要求）**：转办待办（§3.2）、催促（§3.3/§3.4）、经办提交（§4.4）、转办提交与次转提交（§5.1）等每次只涉及单个督办事项的场景，消息内直接附：事项编号、交办内容、上一次反馈三要素（落实情况/存在困难/下一步计划）。
- **多事项待办只列摘要（09-18 PM 要求）**：经办人新增场景（§3.1）一次多条时，最多渲染 3 条「事项编号 + 交办内容」，超出以「……等共 N 条」收尾，完整清单指向右侧台账面板。
- **首次督办无上次反馈**：`{落实情况}`/`{困难问题}`/`{下一步计划}` 渲染为「（首次督办，暂无上次反馈）」。
- **逐级通知不跨级（D-29/AGT-12）**：督办人下发批次→经办人；转办/再转→接收方收待办；次转提交→仅转办人；转办提交→仅经办人；经办提交→仅督办人。越级代提（D-30/D-39）仅通知代提后的新节点归属人。
- **频控（AGT-07，v1.1）**：22:00–8:00 的消息延迟至次日 8:30 合并发送；每收件人每日 IM 通知 ≤5 条（跨场景合计，取代原「催办类 ≤2 条、超出顺延次日」口径，规则见 §7.4）；催促类按批次聚合（§7.2）、提交回执滚动合并（§7.3）。
- **提交即审核**：各级提交回执即视为上一级审阅通过，无独立审核通知。
- **事项级风险/逾期（T7/T8）仅通知督办人**、可视化只在 GUI 看板，无独立催办文案（D-37/D-44）；本清单不含 GUI 看板内文案与导出 Excel 的文件名/表头文案。

## 7. 消息聚合与频控总规则（v1.1）

> 治理目标：批次 × 事项 × 场景三维叠加（且一人常兼多角色）导致的各角色消息爆炸。总原则：**明细事件只进台账与「待处理事项 N」徽标（D-41），IM 消息只承载「需要你行动」的摘要**。

### 7.1 聚合单元与缓冲

- 统一聚合单元 = **收件人 × 批次 × 场景类型**；所有通知先进聚合缓冲，不再按事项直发。
- 聚合缓冲中的明细（事项编号/交办内容/触发事件）全部落台账与徽标计数，消息体内最多渲染 3 条明细（沿用 §3.1 渲染规范）。

### 7.2 催促类聚合（§3.3 / §3.4）

- 由「每事项 1 条」改为**每批次 1 条**：批内仅 1 条事项时退化为 v1.0-final 单事项文案（措辞 A/B 不变）；多条时改用聚合摘要文案。
- 临期摘要（措辞 A，督办直接下发）：

> 文案：`{姓名}`，你好，督办人`{来源姓名}`向你交办的督办批次`{批次编号}`有`{临期数量}`条事项已临近填报时限，请尽快通过右侧台账面板完成填报：
> 1. 事项编号`{事项编号1}`：`{交办内容1}`
> 2. 事项编号`{事项编号2}`：`{交办内容2}`
> 3. 事项编号`{事项编号3}`：`{交办内容3}`
>
> （最多渲染 3 条；超过 3 条时第 3 条后接「……等共`{临期数量}`条，完整清单见右侧台账面板」）谢谢。

- 临期摘要（措辞 B，经转办）：`{姓名}`，你好，经办人`{来源姓名}`转办给你的督办批次`{批次编号}`有`{临期数量}`条事项已临近填报时限，请尽快通过右侧台账面板完成填报：……（明细与收尾同上，逐字替换）
- 逾期摘要：同上两句式，「已临近…请尽快」替换为「已超过…请立即处理上报」，`{临期数量}` 替换为 `{逾期数量}`。

### 7.3 提交回执滚动合并（§4.4 / §5.1）

- 同批次回执按收件人聚合，满足任一条件即发 1 条：**距上一条该批次回执 ≥30 分钟**、或**批内自上次合并后累计 ≥5 条新增已提交**；不满足则继续累积。
- 例外即时单发：跨批次提交、督办人显式关注的事项。
- 合并回执文案（单事项回执文案不变，仍为 v1.0-final 模板）：

> 文案：`{姓名}`，你好，`{提交人姓名}`在督办批次`{批次编号}`新提交了`{新增已提交数量}`条事项，本批次已提交`{已填报数量}`/`{批次事项总数}`条，你可以通过右侧台账面板跟进详情：
> 1. 事项编号`{事项编号1}`：`{交办内容1}`
> 2. 事项编号`{事项编号2}`：`{交办内容2}`
> 3. 事项编号`{事项编号3}`：`{交办内容3}`
>
> （最多渲染 3 条；超过 3 条时第 3 条后接「……等共`{新增已提交数量}`条，完整清单见右侧台账面板」）谢谢。

### 7.4 全局日预算与夜间窗口

- **每收件人每日 IM 通知总预算 ≤5 条（跨场景合计）**，取代 v1.0「催办类 ≤2 条、超出顺延次日」（顺延会造成次日轰炸）；超出部分并入当日一条「今日督办摘要」（AGT-07 同步修订）。
- 22:00–8:00 消息延迟至次日 8:30 合并发送（AGT-07 不变）。
- 今日督办摘要文案：

> 文案：`{姓名}`，你好，今日你有`{事项数量}`条督办通知因超出每日消息预算而聚合为摘要，涉及`{批次数量}`个批次，请通过右侧台账面板查看全部待办，谢谢。

### 7.5 去重与失效

- **失效**：事项已填报/已转办后，其在聚合缓冲中排队未发的催促自动作废。
- **去重**：同一事项同日被多角色触发催促，只保留 1 条（归属当前节点归属人）。
- **连续逾期**：不逐日叠加消息，保持 1 条/日；逾期第 2 天起在逾期摘要末尾追加「（已逾期`{逾期天数}`天）」并维持「请立即处理上报」措辞。

### 7.6 角色级接收策略

- 一人多角色（如督办人兼经办人）时，可按「角色 × 场景类型」配置三档：**即时 / 合并 / 仅徽标**。
- 默认档位：待办下发（§3.1）、转办到达（§3.2）、导入回执（§4.1）、DDL 到达（§4.3）= 即时；催促（§3.3/§3.4）、提交回执（§4.4/§5.1）= 合并；事项级风险/逾期 = 仅 GUI 看板不推送（D-37/D-44 不变）。

### 7.7 统一聚合卡模板

- 所有合并消息统一结构：**一行结论 + ≤3 条明细（事项编号 + 交办内容）+「完整清单见右侧台账面板」+「谢谢。」**，与 §3.1 既有结构对齐；不逐场景定制明细格式。
