## 主线二：数字员工

**近期行动（9 月）**

1. **组织化管理审批流建模**（1.4.0 前置，9 月内启动）
   - 事项：细化 `org-agent-management-p0.md` O-1 状态机（草稿→提交→HR 审核→入通讯录→赋能部配置→上岗→停用/注销），明确每步操作人、表单字段、通知方式（复用 IM 通知）；设计操作留痕格式。
   - 产出：审批流模型文档（状态图 + 字段表）。
   - 验收：状态机覆盖全部迁移路径；每步留痕字段定义完整。

2. **通讯录联动方案**（1.4.0 前置，9 月内启动）
   - 事项：数字员工纳入企业通讯录的数据链路（来源：HR 配置 → 通讯录 → IM 可见），「数字员工」标识与检索标签设计；停用/注销的同步链路。
   - 产出：通讯录联动方案（含与组织主数据的接口约定草案）。
   - 验收：方案通过评审，接口约定可被研发直接排期。

3. **龙小督岗位说明书草案**（9 月下）
   - 背景：纪要「数字员工定位初级岗位（登记、分发、归集），不追求全能」。
   - 事项：为龙小督起草岗位说明书（职责边界、超范围请求的拒绝/转交话术、能力边界），作为 org-agent-management O-3 的第一个实例。
   - 验收：说明书过 PM 评审。

4. **权限分散接入规范草案**（9 月下，与多维表格主线协同）
   - 事项：平台侧「系统级访问清单」schema（见 fields.md SystemAccessGrant）+ 与各业务系统约定的接入规范（系统标识、授权流程、审计回传）。
   - 验收：规范草案过评审。

**依赖**：组织主数据/通讯录系统（跨系统）；issue-14 运行时。

## 主线三：督办场景（最高优先级：9/9 定稿）

**近期行动（9 月）**

1. **督办 V1 定稿评审材料**（**9/9 前**，本周内）
   - 事项：以 `supervision-p0.md`（S-1~S-5 全闭环）为评审主体，补齐四份附件：
     1. Teable 督办台账表结构草案（与主线四行动 3 同一份）；
     2. 催办规则配置示例（ReminderRule：批次级默认 + 事项级覆盖，含 IM/邮件渠道）；
     3. 责任人回复自动入库流程图（回复→识别→润色→确认→写表）；
     4. 每日汇总报告模板（四分区：当日进展/已催办及反馈/逾期未反馈/明日临近截止）。
   - 验收：9/9 评审通过，V1 方案定稿。

2. **回复自动入库 PoC**（9 月下，1.3.1 前置）
   - 事项：用 10~15 条真实风格的责任人回复样本验证自动识别 + 行文润色准确率；验证「不脑补、不篡改、保留负面事实」铁则的自动化边界（识别置信度低时必须转人工确认）。
   - 产出：PoC 报告（准确率 + 失败案例分类）。
   - 验收：准确率达标（阈值待定，建议 ≥85% 自动通过、其余转人工）。

3. **行文风格 Skill 测试集**（9 月中，与行动 2 并行）
   - 事项：整理 20 条测试样本（含负面案例：联系不上、对方拒绝、无法办结），作为 Skill 回归测试集归档。

4. **1.3.1 开发排期**（9/9 定稿后）
   - 事项：S-5 闭环（催办规则引擎、催办历史、每日汇总定时任务）+ 工作台首页督办数据源（F-W03）排期。
   - 验收：排期进入 1.3.1 版本计划。

**依赖**：多维表格主线（台账表结构）；邮件主线（催办邮件渠道，1.4.1 前可先 IM）。
