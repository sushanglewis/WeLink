# PRD: 2026-09-07-supervision-gui-form

<!-- status: draft -->

> **概述**：2026-09-07 业务方明确 IM 督办两大目标——(1) 基于督办台账建设美观 GUI 看板（指标 + 列表 + 跟进记录下钻）；(2) 龙小督在 IM 聊内以消息表单方式推送填报任务，经办人逐条查看、填报、提交（一人可能有多项）。本文档只定义业务规则与产品体验，技术方案由研发定义，本文档不做技术决策。全部 PM 决策见文末「决策记录」。

## 产品目标

1. **督办看板 GUI（领导只读总览）**：面向领导/管理层，将督办任务与跟进记录以任务导向看板呈现——指标卡（D-22 双字段口径 7 张）、**筛选条件框可组合筛选**的事项列表、点击行下钻跟进记录时间线，GUI 无任何写操作入口。
2. **DM 右侧 panel 逐条填报（含转办/润色，D-24/D-30）**：经办人、转办人在龙小督 DM 的**右侧扩展 panel（龙小督台账，D-27）** 中以「第 k / 共 N 项」导航逐条填报五字段（落实/困难/下一步/预计完成时间/进度评价），支持**单项提交、转办（弹窗选人）、龙小督润色、暂存续填**（D-20 无申请办结/审核）；panel 宽度可拖拽、可覆盖聊天区；自然语言输入走会话底部**与聊天窗口共用的输入窗口**——用户可口述进展由龙小督**代填预填**（核对后提交），也可直接手填。**台账按「督办批次（文件来源）> 事项编号 > 事项详情」三级层级展示（D-29）**：批次含督办日期与批次 DDL（口头约定、默认 36h），事项级不再设 DDL；列表展示节点状态（处理中/审核中/暂存中），修改/润色后仅为暂存，点提交才以提交人身份写入跟进记录表；提交按相邻前置角色逐级通知审核。
3. **业务闭环**：任务下发唯一方式 = 督办人发送 Excel 给龙小督（解析校验→落库〔事项跟进状态=暂存〕→督办人启动督办后通知经办人，下发即接收 D-13）；全部事项遵循双字段状态机（事项状态 4 值 + 事项跟进状态 4 值，两字段完全独立，D-22/v0.6）；24h 填报监督；进入风险窗（截止前 7 天）/逾期未填报/逾期自动提醒 = 原表单加急 + 消息通知 + 加急可视化，不加新表单、无需人工点击（D-15），其中**进入风险必须通知经办人（D-23）**；逾期未填报同步通知督办人跟进（T3），逾期升级督办人（只读视图 → 系统自动 IM+邮件提醒）；填报闭环按双字段状态机（D-22+D-20）：提交→已填报（存为填报消息可回看）→督办人 DDL 查收（直接修改保存/导出 Excel，无审核、无办结按钮）→**导出 Excel 后本轮关闭、已填报回暂存（D-21 触发不变，T5）**；完结=上级督办室线下同意后督办人在台账手动将事项状态 改为完结（终态、不再被督办），延期=督办人回改截止时间、事项状态 按新锚点重置（D-22/v0.6）；转办链最多「经办人→转办人→次级转办人」三级；消息列表龙小督会话旁展示督办状态徽标（待填报事项数，区别于未读数，D-14）；批示过问本期不做（D-17）。
4. **数据闭环**：提交只写跟进记录表（记录人=实际填报人），主表反馈字段由系统自动同步；状态字段规范化单选；操作全量留痕。
5. **桌面端外壳改造（D-25）**：左侧功能菜单可收起为纯 icon bar、聊天列表可收起，配合 D-24 panel 拖宽形成全宽专注填报；聊天列表龙小督条目同时展示未读消息数与**待办事项数量徽标**（区别于未读数）。

## 非功能需求

- **身份与安全**：所有操作以本人身份执行与留痕，身份与事项不匹配时拒绝操作；润色仅建议、经用户确认才生效；数据按身份隔离（经办人仅见本人相关事项）。
- **性能**：看板首屏 < 2s；表单预填 < 1s；组合筛选响应快；台账 panel 拖拽流畅。
- **兼容性**：一期桌面端为主；二期移动端直填；降级链接全端可用。
- **持久性**：表单草稿与批次状态服务端保存（D-12），会话中断恢复不丢已填内容。
- **可维护**：状态值集与指标口径集中维护，避免多处口径不一致。
- **审计**：填报（记录人=填报人）、转办、提醒、改评全量留痕（审批在线下完成，不在系统内）。

## 发布标准

- [ ] 指标卡（D-22/v0.6 双字段口径，事项状态=完结 的事项不出现在任何指标）与督办台账人工核对一致；筛选条件框组合筛选正确、表头排序正确；分页（页大小切换/翻页）正确且指标卡不受分页影响。
- [ ] GUI 无任何写操作入口；经办人仅见本人相关事项。
- [ ] 表单 k/N 导航、单项提交必填校验（报错文案「{编号} {字段}不能为空」）、暂存续填、润色确认替换、转办全链路正确；操作按钮按 D-30 映射矩阵渲染（无批量操作）；提交后状态=已填报。
- [ ] 督办人查收/逾期视图无催办按钮；逾期未填报项可直接修改/代录补正并提交（留痕），经办人侧提醒由系统自动发出（IM 即时、邮件渠道未就绪时记录待补发）。
- [ ] 24h 填报监督触发准确；频控生效（非工作时间延迟、催办类 ≤2/日）。
- [ ] 提交写入跟进记录（记录人=填报人）、主表自动同步及时；状态字段规范化与历史数据清洗完成。
- [ ] 重复提交安全、越权访问拦截、审计留痕生效。
- [ ] 表单持久化：session 内切换后再回聊天窗口表单仍在，现场（已填/暂存/k-N 位置）完整恢复。
- [ ] 提交存档消息以用户身份落入聊天历史，内容（五字段摘要+进度评价）与跟进记录表一致；表单该项转为只读。
- [ ] Excel 下发：解析校验、失败行逐条反馈、经办人收卡片链路正确（D-13）。
- [ ] 消息列表督办徽标计数与表单待办一致（提交 -1、完成消失），与未读红点视觉区分；加急时转红（D-14/D-15）。
- [ ] 自动催办不产生新表单/新卡片；原表单加急可视化（标红+横幅+角标）与 push 消息送达（D-15）。
- [ ] 完结与延期：督办人在台账手动将事项状态 改为完结（审计留痕、经办人收通知、该项退出待填报/风险/逾期/催办全部链路）；回改截止时间后事项状态 按新锚点重置（D-22/v0.6）。
- [ ] 督办批次按督办日期近→远排序；批次 DDL 默认 36h、口头约定可覆盖；推进中事项 DDL 继承所属批次，无批次单事项场景按单事项 DDL 判定（D-29）。
- [ ] 导出 Excel（导出入口在批次卡片）后该批所有事项节点回「事项暂存中」；逐级提交仅通知相邻前置角色、不跨级；提交即审核、系统无审核按钮（D-29）。
- [ ] 剧本走查通过。双字段状态机迁移与迁移表一致（T1–T8，两字段独立、事项状态 纯时间口径），本轮关闭回暂存、完结退出全部监控正确（D-20/D-22 v0.6）。
