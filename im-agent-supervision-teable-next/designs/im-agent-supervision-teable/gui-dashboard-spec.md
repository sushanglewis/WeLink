# GUI 看板方案：督办事项展示界面

<!-- status: draft -->

- **日期**: 2026-09-09 v0.8（v0.5 指标卡与状态筛选按状态机 6 值重映射（D-19）；v0.6 按 D-22 双字段改造；v0.7 按 PM 口径改列表与下钻（21 列 + 跟进明细）；**v0.8 按 PM 修正 D-22**：两字段完全独立——**状态1=状态机1（正常/风险/逾期/完结，纯时间计算，完结督办人手动）**、**状态2=状态机2（暂存/推进中/已填报/逾期未填报，无办结）**，见 `state-machine.md` v0.6）
- **上游**: `requirements/2026-09-07-supervision-gui-form/prd.md`、`role-scenarios.md`
- **目标版本**: 1.3.1
- **定位**: **领导/管理层只读总览**（D-5）：全部督办事项列表 + 下钻跟进记录 + 统计指标；列表经**筛选条件框组合筛选 + 表头点击排序**（D-9）；无编辑入口。

## 1. 目标与范围

将 Teable「督办任务 + 跟进记录」两表以任务导向看板呈现。本期**纯只读**（D-5）：展示、筛选、下钻；编辑动作（填报/转办/催办/办结审批）一律在 IM 表单/消息中完成（见 `embed-form-spec.md`）。领导通过 GUI 总览，督办人/经办人也可使用（经办人默认过滤本人）。

## 2. 架构路线评估（供研发决策）

| 路线 | 描述 | 优点 | 缺点 | 结论 |
|------|------|------|------|------|
| A. 前端直连 Teable API | 页面直接调 `/api/table/{tableId}/record` | 无后端、实时数据、MVP 最快 | schema 变更破坏前端；权限/审计碎片化；多表聚合 N+1；速率限制天花板 | 仅适合原型 |
| B. Teable + 轻量 BFF（推荐） | 薄后端封装 Teable API，暴露任务导向接口 | 隔离 schema 变更；统一鉴权审计缓存；前端只关心 UI | 需维护一层服务 | **推荐**，符合 `gui-route-teable-bff.md` 研究结论与会议纪要 |
| C. Teable App Builder | 官方 AI 生成应用 | 零代码 | 生成物可控性差；列级筛选/口径/权限定制难 | 不选 |

**推荐架构**：`IM 客户端 / 浏览器 → 督办 BFF → Teable REST API（持有 Token）→ PostgreSQL`。
- BFF 承担：身份映射、字段 ID 适配层（schema 变更只改 BFF）、指标聚合、列级筛选翻译（前端筛选条件 → Teable filter）、跟进明细组装、审计日志、表单接口（见嵌入方案）。
- 缓存：指标聚合短 TTL（60s）；列表直透。

### 2.1 BFF 首批接口（草拟）

| 接口 | 说明 |
|------|------|
| `GET /supervision/metrics` | 指标卡聚合（口径见 §4） |
| `GET /supervision/tasks` | 事项列表；支持**筛选条件框任意字段组合筛选**（D-9）、表头点击排序、分页 |
| `GET /supervision/tasks/{id}` | 事项详情（全字段，含转办人/批示/催办历史） |
| `GET /supervision/tasks/{id}/follow-ups` | 跟进明细：责任链（督办人/经办人/转办人/次级转办人）+ 部门反馈三字段 + 督办时间/填报完成时间/转办时间/次级转办时间 + 响应时长（BFF 计算，小时一位小数）+ 跟进记录时间线（倒序） |
| `GET /supervision/form-batch?assignee=` | 经办人填报批次 + 上次进展预填 |
| `POST /supervision/form-batch/submissions` | 表单提交（写跟进记录表） |
| `POST /supervision/form-batch/transfer` | 转办（写主表转办字段） |
| `POST /supervision/remind` | 督办人催办（IM+邮件通知经办人） |

## 3. 页面结构

```
┌──────────────────────────────────────────────────────────┐
│ 指标卡：总数 │ 推进中 │ 已填报 │ 暂存(在库) │ 逾期未填报 │ 风险 │ 逾期 │
├──────────────────────────────────────────────────────────┤
│ 列表（21 列，筛选条件框 + 表头 ▲▼ 排序，D-9）：               │
│ 编号│任务名称│交办事项│三反馈│责任单位│经办人│截止▲│交办│预完│评价│状态1│状态2│来源│…│
│  SJ… │ …      │ …      │ …   │ …     │ …   │09-12│09-01│09-15│推进中│正常│推进中│Excel│…│
│ 分页栏：共 N 条 · [10 ▾] 条/页 · ‹ 1 2 3 ›（指标卡不受分页影响）│
├──────────────────────────────────────────────────────────┤
│ （点击行 → 右侧滑出抽屉）事项关键信息 + 跟进明细 + 记录时间线  │
└──────────────────────────────────────────────────────────┘
```

- **列表字段（21 列，PM 口径，有序）**：任务编号、任务名称、交办事项、部门反馈的落实情况、部门反馈的存在困难、部门反馈的下一步计划、责任单位、经办人、截止日期（截止时间）、交办时间（交办日期）、预计完成时间、进度评价、**状态1**（=状态机1〔时间状态〕：正常/风险/逾期/完结）、**状态2**（=状态机2〔跟进状态〕：暂存/推进中/已填报/逾期未填报）、任务来源、板块类别、事项类别、部门负责人、部门主管、督办人、经办人账号（PM 清单中第二个「经办人」按账号字段实现）；状态1/状态2 列各带状态色（同指标卡），任务来源/板块类别/事项类别/部门负责人/部门主管为主表新增或复用字段（字段 ID 实现期补充）。
- **指标卡**：数值 + 状态色（逾期未填报橙红 / 风险橙 / 逾期红 / 完结置灰；状态定义与迁移见 `state-machine.md` v0.6，D-22 口径：风险=截止前 7 天、逾期=过截止（状态1 纯时间计算，与填报无关）、逾期未填报=超期未反馈（过督办DDL，状态2）；总数不含状态1=完结 的事项；风险/逾期读状态1 字段，推进中/已填报/暂存/逾期未填报读状态2 字段）。
- **筛选条件框**（D-9）：**状态1**（正常/风险/逾期/完结 4 值）+ **状态2**（暂存/推进中/已填报/逾期未填报 4 值）两个筛选器，与责任单位/经办人/截止时间区间等任意字段组合筛选，可一键清空。
- **表头排序**：点击列头 ▲▼ 切换排序字段与方向（默认截止时间升序）；逾期行红边条、逾期未填报行橙红边条、风险行橙边条；状态1/状态2 列分别展示状态机1/状态机2 的状态值，状态1 异常态另以边条/角标呈现（D-22）；点击行右侧滑出抽屉下钻。
- **列表分页（GUI-08）**：底部「共 N 条 + 页大小（10/20/50，原型以 5 条/页演示双页）+ 翻页」；**指标卡始终按筛选后全量计算，与分页无关**；翻页/改页大小保留筛选与排序状态。
- **已转办展示态**：转出价视角（经办人看到已转出的项、转办人看到再转出的项）状态列叠加「已转办」橙色标识（tooltip 注明口径仍按真实状态计入）；真实状态值不变，仅展示层叠加。
- **进度评价**：单选三值 **推进中 / 已落实 / 已滞后**（PM 2026-09-08 确认，D-6 双方可改并留痕）。
- **下钻抽屉**（PM 口径）：上半区**事项关键信息**（任务编号/任务名称/交办事项/责任单位/状态1/状态2/进度评价/截止日期/交办时间/预计完成时间/任务来源/板块类别/事项类别/部门负责人/部门主管/督办人/领导批示/已催办时间）；下半区**跟进明细**——责任链：**督办人、经办人、转办人（如有）、次级转办人（如有）**；部门反馈三字段（落实情况/存在困难/下一步计划，展示最新一条，可展开全文）；**督办时间**（督办人上传 Excel 并导入成功的时间，BFF 落库时记录，PM 口径）；**填报完成时间**（五要素被填报的时间 = 跟进记录创建时间）；**转办时间**（经办人转给转办人的时间，如有，取主表转办人字段首次写入时间）；**次级转办时间**（转办人转给次级转办人的时间，如有，取次级转办人字段首次写入时间）；**响应时长**（= 填报完成时间 − 督办时间，单位小时、精确到小数点一位，BFF 计算；多次填报按首次填报完成时间计算，时间线逐条展示各自填报完成时间）；底部跟进记录时间线（倒序：每次五字段 + 填报人 + 填报完成时间，可展开全文）。
- **只读约束**（D-5）：页面无任何写操作入口；批示/审批/催办引导至 IM（龙小督消息）。
- **权限**：领导/管理员全量；督办人全量；经办人默认仅本人（按经办人账号字段过滤，可切换「我经办的/我转办的」视角，转办后事项保持可见）。

## 5. 数据一致性与性能

- 只读看板，数据实时来自 Teable（指标卡 60s 缓存）。
- 首屏 metrics + 列表 < 2s；分页 50/页；组合筛选由 BFF 翻译为 Teable filter 一次查询，避免前端多次往返。
