## 1. 状态定义（两个独立字段）

### 1.1 事项状态（时间状态字段，主表新增，单选 4 值）

| 状态 | 含义 | 进入条件 |
|------|------|----------|
| **正常** | 当前时间未进入截止前 7 天 | Excel 下发落库默认；回改截止时间后按新锚点重算 |
| **风险** | 当前时间进入**截止时间前 7 天**（`今天 ≥ 截止−7d`） | BFF 定时判定（催经办人，D-15） |
| **逾期** | 当前时间**晚于截止时间**（`今天 > 截止`） | BFF 定时判定（逾期升级督办人，D-4） |
| **完结** | 事项办结；**终态** | **督办人手动修改**该字段为完结（上级督办室线下同意，聊内不做审批，D-20）；完结后锁定，不再参与风险/逾期计算、不再被督办 |

- **独立计算（D-22 修正）**：事项状态 只看**当前时间与截止时间**，与事项跟进状态 取值、与五要素是否填报**完全无关**——已填报的事项到点照样进入风险/逾期（用于提示任务整体临期/超时）；完结除外。
- **完结锁定**：事项状态=完结 的记录，BFF 跳过全部监控/催办/预警计算与通知，不出现在待填报徽标、风险/逾期指标中。
- **延期**：不设状态值。不同意完结（或认为不该完结）时，由**督办人手动在 Teable 回改「截止时间」**；BFF 按新锚点（新截止−7d / 新截止）重新计算事项状态；完结项不回算。

### 1.2 事项跟进状态（跟进状态字段，主表「状态」改造，单选 4 值）

| 状态 | 含义 | 进入条件 |
|------|------|----------|
| **暂存** | 在库事项：已落主表，督办人尚未启动本轮跟进 | Excel 下发落库（D-13）；或上一轮导出关闭后回到在库（T5） |
| **推进中** | 督办人已启动本轮跟进，等待经办人填报五要素 | 督办人启动督办（T1）；或上一轮逾期未填报项重启（T6） |
| **已填报** | 经办人/转办人/次级转办人已提交五字段，等待本轮关闭 | 推进中/逾期未填报提交五字段（T2/T4） |
| **逾期未填报** | 超过**所属督办批次的批次 DDL** 仍未填报（=超期未反馈；**DDL 双轨 D-29**：推进中事项 DDL=所属批次 DDL，无批次单事项场景保留单事项 DDL） | BFF 定时判定 `今天 > 批次DDL`（T3）；可补报回已填报（T4） |

- **提交不受事项状态 限制**：风险/逾期（事项状态）仍可填报（T2/T4），填报只影响事项跟进状态。
- 转办不改变任一字段：转办仅转移「当前填报责任人」；已转办项在转出价视角只读留痕（D-8 不变）。

## 4. 数据落点

- 主表两个独立单选：**事项状态**（新增，4 值：正常/风险/逾期/完结，BFF 按截止时间定时计算，完结手动）+ **事项跟进状态**（原「状态」`fldgIYI60Lz5ztzMANG` 改造，4 值：暂存/推进中/已填报/逾期未填报）；历史数据清洗映射表 PM 确认后执行（见 §5 映射建议）。
- 「批次 DDL」字段落**督办批次表**（本轮反馈截止，逾期未填报由此判定；DDL 双轨 D-29：推进中事项 DDL=所属批次 DDL，无批次单事项场景保留单事项 DDL）与「截止时间」字段（事项状态 风险/逾期由此判定）需在主表新增/复用；上一轮导出关闭后，下一轮随新 Excel 生成新批次与批次 DDL；延期 = 督办人回改「截止时间」。
- 完结/延期留痕：督办人手动修改事项状态=完结写审计日志（谁/何时/事项）；回改截止时间由 Teable 字段历史自然留痕，跟进时间线可见。
- 督办人查收/修改留痕：督办人在查收表单中的保存写跟进记录表（创建人=督办人）；导出 Excel 动作写审计日志（谁/何时/范围）。
- T3/T7/T8 判定为 BFF 定时任务（对齐 D-15：催办与升级均不生成新表单）。

## 6. 验收

- [ ] 两字段独立：事项状态 仅按当前时间×截止时间计算（已填报项到点仍进入风险/逾期；完结项锁定除外），事项跟进状态 迁移不受事项状态 影响；回归 T1–T8 全链路。
- [ ] 完结：督办人在 Teable 手动将事项状态 改为完结后，该项不再出现在风险/逾期指标、待填报徽标、催办/预警任何链路；经办人收到完结通知；修改动作审计留痕。
- [ ] 事项跟进状态 闭环：暂存→推进中→已填报（T1/T2）、过批次 DDL 转逾期未填报（T3，D-29 双轨）可补报（T4）、导出关闭回暂存（T5）、逾期未填报 下轮重启（T6）；事项跟进状态 无「办结」值。
- [ ] 锚点准确：`截止−7d` / `批次DDL` / `截止` 三个判定（含跨天、时区）；延期回改截止时间后事项状态 按新锚点重算。
- [ ] 节点状态机（§7）：7 值迁移链、提交即审核（无审核按钮）、逐级通知不跨级、导出归档节点回「事项暂存中」（D-29）。
- [ ] 暂存→推进中按批启动；批次 DDL 到达后推送 supervisor 查收表单（无审核按钮、无办结按钮、提交即审核 D-29）；导出 Excel 后已填报项回暂存、逾期未填报项保持原状态留痕。
- [ ] 风险/逾期未填报/逾期的可视化（看板徽章、表单标红、徽标转红）与新状态一致；「紧急」在状态值、指标、筛选、可视化中全部移除。

## 7. 节点状态机（D-29，第三字段）

> 与事项状态、事项跟进状态**完全独立**的第三个字段；节点「事项暂存中」≠ 事项跟进状态「暂存」。

- **字段**：节点状态（单选 **7 值**，落**跟进记录表**，PM 2026-09-11 确认）+ 业务事件节点日志（时间+操作人+事项+前后节点）。
- **7 值**：事项暂存中（初始/归档态）/ 经办人处理中 / 转办人处理中 / 次级转办人处理中 / 转办人审核中 / 经办人审核中 / 督办人审核中。
- **台账业务展示名（D-31，字段值不变）**：事项暂存中=暂存（在库）、经办人处理中=待经办人处理、转办人处理中=待转办人处理、次级转办人处理中=待次级转办人填报、转办人审核中=待转办人提交、经办人审核中=待经办人提交、督办人审核中=待督办人提交；徽标附当前节点归属人（谁头上待办）。
- **迁移链**：督办人下发→经办人处理中→（经办人转办）转办人处理中→（转办人再转）次级转办人处理中→次转提交→转办人审核中→转办人提交→经办人审核中→经办人提交→督办人审核中→**督办人导出 Excel 归档→回事项暂存中**（T5 同步）。
- **提交即审核（PM 2026-09-11）**：系统**不设审核功能按钮**；下一级提交即视为上一级审阅通过并上报，提交记录以**提交人 Token** 写入跟进记录表留存。「审核中」节点=等待上一级查看内容后再提交，审核动作即「查看+提交」。
- **逐级通知（不跨级）**：督办人下发批次→通知对应经办人；转办/再转办→接收方收待办事项通知；次转提交→仅通知转办人、转办人提交→仅通知经办人、经办人提交→仅通知督办人。
- **协作者信息**：节点对应成员（督办人/经办人/转办人/次级转办人）随事件留痕，供台账详情与审计查询。
