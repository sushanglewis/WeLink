## 1. 指标卡（7 项）

### M1 事项总数
- **业务口径**: 当前角色可见的全部督办事项总量，**含已办结**（领导/督办人=全表；经办人=本人经办；转办人=本人经办+本人被转办；次级转办人=本人执行+本人被转办）；事项状态=完结 的事项不再被督办、不参与风险/逾期，但仍计入总数（D-22/v0.6，PM 2026-09-10 修订）。
- **技术口径**: `count(全部可见记录)`（不过滤完结，v0.8）；先行身份过滤。
- **可计算**: ✅ 依赖事项状态 字段新增（D-22）。

### M2 推进中
- **业务口径**: 督办人已启动本轮跟进、等待填报五要素的事项数。
- **技术口径**: `count(事项跟进状态 == "推进中")`。
- **可计算**: ✅ 依赖事项跟进状态 单选改造（D-22）。

### M3 已填报
- **业务口径**: 填报人已提交五字段、等待本轮关闭（督办人导出 Excel 后回暂存）的事项数。
- **技术口径**: `count(事项跟进状态 == "已填报")`。
- **可计算**: ✅。

### M4 暂存（在库）
- **业务口径**: 已落库但督办人尚未启动本轮跟进（或上一轮导出关闭回到在库）的事项数。
- **技术口径**: `count(事项跟进状态 == "暂存")`。
- **可计算**: ✅。

### M5 风险
- **业务口径**: **当前时间进入截止时间前 7 天**且未完结的事项数（D-21 锚点不变；事项状态 纯时间口径，与是否填报无关）。
- **技术口径**: `count(事项状态 == "风险")`；由 BFF 定时判定 `今天 >= 截止 - 7d` 且未完结（见 `state-machine.md` T7）。
- **可计算**: ✅ 依赖事项状态 字段新增（D-22）。

### M6 逾期未填报（超期未反馈）
- **业务口径**: **超过督办人设定的反馈 DDL 仍未填报**的事项数——即 **超期未反馈**（事项跟进状态 口径；已通知督办人跟进）。
- **技术口径**: `count(事项跟进状态 == "逾期未填报")`；由 BFF 定时判定 `今天 > 批次DDL` 且未填报（见 `state-machine.md` T3）。
- **可计算**: ✅。看板卡片标题「逾期未填报」，副标题/悬浮说明标注「超期未反馈（过督办反馈 DDL）」口径。

### M7 逾期
- **业务口径**: **当前时间晚于截止时间**且未完结的事项数（D-21 口径：逾期挂任务完成时限字段，不挂督办反馈 DDL）。
- **技术口径**: `count(事项状态 == "逾期")`；由 BFF 定时判定 `今天 > 截止` 且未完结（见 `state-machine.md` T8）。
- **边界**: 逾期（事项状态）后仍可填报（只影响事项跟进状态）；完结后事项状态 锁定退出。
- **可计算**: ✅。

## 2. 列表统计列（2 项）

### C1 跟进次数
- **业务口径**: 该事项在跟进记录表的填报记录条数。
- **技术口径**: `len(跟进记录 link字段 fldtlBTGjscwsUjNfiU 的关联记录数组)`；Teable API 返回 link 单元格为记录数组，直接取长度。
- **可计算**: ✅ link 字段现网已存在。

### C2 催办次数（暂不可计算，需数据改造）
- **业务口径**: 该事项被催办的总次数。
- **现状**: `已催办时间 fldTT1NyS43RYDiHTUD` 为自由文本单字段，无法结构化计数。
- **技术方案（二选一，建议 A）**:
  - A. 对齐 S-5 新建「催办记录表」（事项 link + 催办时间 + 渠道 + 操作人），`count(催办记录 where 事项=本记录)`；
  - B. 过渡方案：BFF 催办接口将时间追加写入 `已催办时间`（分号分隔时间戳），BFF 解析计数。
- **可计算**: ❌ 现状不可；按方案 A/B 改造后可算。原型中展示为静态 mock。
