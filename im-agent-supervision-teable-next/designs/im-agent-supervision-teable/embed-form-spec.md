## 1. Mattermost 嵌入能力评估结论

| 途径 | 能力 | 结论 |
|------|------|------|
| vanilla Mattermost 消息 | 仅 markdown，不支持聊内 iframe | 不可用 |
| Mattermost webapp plugin | WeLink IM 为自研客户端，plugin 不生效 | 不选 |
| **自研 IM 客户端消息卡片** | 客户端识别 `supervision_form_card` 消息 → 气泡内渲染 iframe（issue-6 同机制） | **选用** |

约束与对策：iframe 高度 postMessage 自适应；移动端 WebView 二期；加载失败自动降级链接卡片。

## 2. 消息卡片协议

### 2.1 消息载荷（agent 发送）

```json
{
  "type": "supervision_form_card",
  "version": 2,
  "batch_id": "bch_20260908_zhangsan",
  "form_url": "https://supervision-bff.example.com/form/bch_20260908_zhangsan?sig=...",
  "view_mode": "edit",
  "urgency": "normal",
  "title": "督办事项进展填报",
  "summary": "共 5 项，最近截止 9 月 12 日",
  "deadline": "2026-09-12",
  "assigned_to": "zhangsan"
}
```

- `deadline`: 督办人设定的填报 **DDL**（不是任务截止时间）；`summary` 中「最近截止」同指该 DDL。
- `view_mode`: `edit`（经办人/转办人/次级转办人填报）| `supervisor`（督办人查收：可修改保存+润色，D-11）| `readonly`（督办人逾期视图：只读+催办手动入口，D-4）。
- `urgency`: `normal | urgent`——自动催办加急时更新（D-15），客户端刷新卡片角标「已加急」；不生成新卡片。
- 客户端校验 type + 域名白名单后渲染：标题 + 摘要 + iframe 容器 + 「新窗口打开」按钮。

### 2.2 iframe ↔ 客户端 postMessage 协议（origin 必须等于 BFF 表单域）

| event | payload | 时机/用途 |
|-------|---------|-----------|
| `resize` | `{height}` | 高度自适应（防抖 200ms） |
| `submitted` | `{batch_id, task_no, submitted, total}` | 单项提交成功，卡片角标「已提交 k/N」 |
| `transferred` | `{batch_id, task_no, to_user}` | 单项转办成功，卡片角标「已转办」 |
| `remind` | `{batch_id}` | 督办人点催办按钮，客户端代理发送催办回执（也可 BFF 直发） |
| `completed` | `{batch_id, submitted, total}` | 全部完成 → 卡片完成态 |
| `urgency_changed` | `{batch_id, task_no, level, deadline}` | 自动催办加急/解除（D-15），客户端更新角标与消息列表徽标 |
| `closed` | `{batch_id}` | 用户关闭表单 |
| `exported` | `{batch_id, file_msg_id}` | 导出 Excel 成功，客户端展示文件消息占位；BFF 生成文件后由龙小督发文件消息（D-20） |

客户端 → iframe：仅 `theme`。

## 2.4 消息列表督办状态徽标（D-14）

- IM 消息列表龙小督会话行渲染**督办状态徽标**（绿色 pill：「督办 · N 项待填报」），与未读红点并存、语义独立；N = 当前用户待填报表事项数（督办人=待查收+逾期未填报数，D-22）。
- 数据源：`GET /supervision/badge`（BFF 按登录态聚合，短 TTL/WS 推送）；与表单 `submitted` 回执同源，提交一项 N-1，批次完成徽标消失。
- 加急联动：催办加急时徽标转红并附「加急」角标（D-15）；点击徽标/会话定位到表单卡片。
- 原型演示：壳页面 `pages/prototypes/shell-kanban.html?view=chat&role=jb`。

## 3. 表单页设计（k/N + 左侧多选列表 + 批量操作）

### 3.1 页面结构

```
┌────────────────────────────────────────────────────────┐
│ 督办事项进展填报      当前第 3 / 共 5 项 ▓▓▓░░  已提交 2 │
├──────────────┬─────────────────────────────────────────┤
│ ☐ ① SJ2608… │ 事项：SJ2609041005 城区道路维修          │
│   09-10  ✓已提交│ 责任单位：市政中心  截止：09-12        │
│ ☐ ② SJ2609… │ ┌ 部门反馈工作落实情况（预填上次）┐      │
│   09-11  ✓已提交│ │ 目前完成路面修补约80%…          │ │
│ ☑ ▸③ SJ26…  │ └───────────────────────────────────┘  │
│   09-12  暂存 │ [龙小督润色]                          │
│ ☐ ④ SJ26…   │ ┌ 部门反馈存在困难问题（预填）┐          │
│   09-15  未填 │ └ ……                              ┘   │
│ ☐ ⑤ SJ26…   │ ┌ 部门反馈下一步工作计划（预填）┐        │
│   09-18  未填 │ └ ……                              ┘   │
│              │ 预计完成时间 [2026-09-12]  进度评价 ○… │
│ [批量提交]   │                                         │
│ [批量转办]   │ [上一项] [暂存] [提交] [转办] │
├──────────────┴─────────────────────────────────────────┤
│ 选中 2 项 · 已提交 2 · 未填 3                           │
└────────────────────────────────────────────────────────┘
```

- **常驻指示器**：头部始终「当前第 k / 共 N 项」+ 进度条 + 已提交计数（D-1）。
- **左侧事项列表**：每项 = 复选框 + 编号 + **督办人设定 DDL（填报截止，区别于任务截止时间）** + 状态标记（**推进中 / 逾期未填报**（状态2）/ **风险 / 逾期 / 完结**（状态1 角标，D-22/v0.6）/ ✓已填报 / ↷已转办 / 草稿）；点击切换右侧明细，当前项高亮；列表支持全选/单选。
- **右侧明细（当前项）**：五字段表单——三反馈 longText（**预填该事项跟进记录表最新一条对应内容**，可改，D-1）、预计完成时间（date，默认主表当前值）、进度评价（单选）。
- **当前项按钮**：
  - `暂存`：服务端草稿，断点续填；
  - `提交`：校验当前项必填后提交，该项 ✓；
  - `转办`：弹出**组织成员选择弹窗**（IM 通讯录，搜索 + 成员列表**单选唯一一位**，未选确认键禁用）→ 确认 → 写主表转办人字段 → IM 通知新执行人（D-1/D-8）；
  - `龙小督润色`（**三个反馈字段各配一个润色按钮**）：对该字段文本调 BFF 润色服务（行文风格 Skill）→ 弹窗展示规范文本 → 用户确认替换（可再编辑，保留原文可撤销；对齐 S-1 铁则：不脑补、不篡改、保留负面事实，D-2）；
- **当前项按钮按角色区分（PM 2026-09-08 确认）**：
  | 角色 | 当前项按钮 |
  |------|-----------|
  | 经办人 | 暂存 / 提交（=保存 Teable+存填报消息）/ 转办（弹窗单选转办人）/ 龙小督润色 |
  | 转办人 | 暂存 / 提交 / 转办（弹窗单选次级转办人）/ 龙小督润色 |
  | 次级转办人 | 暂存 / 提交 / 龙小督润色（**无转办**，链路终点 D-8） |
| 督办人（supervisor **查收**，D-11/D-20，**无审核**） | **提交（保存到 Teable，修改写跟进表创建人=督办人，留痕）** / 龙小督润色 / **导出 Excel（生成后龙小督以文件消息发送至会话，触发本轮关闭 T5）** / **催办（仅逾期未填报/逾期项可点；已填报项禁用展示「已填报无需催办」）** |
  - 已转办事项在执行人表单中标记「↷ 已转办 · {新执行人}」，明细只读留痕，进展仍计入批次汇总。
  - 提交后该项转为「✓ 已填报」并锁定只读（状态机 T2），同时**存为一条填报消息**（算作用户发送的一次聊内表单消息，聊天历史可点击呼出只读表单回看，D-20）；等待督办人到 DDL **查收**（见 §3.3，无审核）。
- **批量操作（左侧多选后）**：
  - `批量提交`：逐项校验必填项，存在空项则报错并逐条列出「{任务编号} {字段名}不能为空」，全部通过才提交（D-1）；
  - `批量转办`：左侧勾选 1~N 项 → 弹出同一**组织成员选择弹窗**（单选唯一一位）→ 确认后所选项统一转办（写主表转办字段 + 逐项 IM 通知新执行人）；未勾选时点击给出提示。
- **催办加急可视化（D-15）**：自动催办不生成新表单——原表单内被催项「截止时间标红 + 加急横幅（⚠ 龙小督已催办加急）」，左侧列表该项 meta 标红「· 已加急」；卡片角标「已加急」、消息列表督办徽标转红（见 §2.4）。
- **全部完成** → `completed` 回执 → 卡片完成态 + agent 汇总回执话术；**无汇总页（D-20）**——每项提交内容以填报消息形式留在会话中可逐条回看。

### 3.2 表单字段 ↔ Teable 映射

跟进记录表 `tbl3Tq7pdThgmvcde7j`（字段 ID 实现期用 Teable Token 全量校验）：

| 表单字段 | 写入字段 | 类型 |
|----------|----------|------|
| （隐藏）任务编号 | link → 主表记录（对称 `fld9AgubUggQALxcX02`） | link |
| 三反馈（落实/困难/下一步） | 对应三个 longText | longText |
| 预计完成时间 | 预计完成时间 | date |
| 进度评价 | 进度评价 | 单选：**推进中 / 已落实 / 已滞后**（PM 2026-09-08 确认；D-6 督办人/经办人均可改，留痕） |

记录创建人 = 实际填报人（经办人/转办人均可能，D-2）。转办动作写主表 `转办人`/`次级转办人` 字段，不写跟进表。

### 3.3 督办人视图（两种，D-4 / D-11）

- **逾期升级（D-4）`view_mode=readonly`**：明细只读、隐藏提交/转办/润色，保留「催办」按钮。
- **DDL 填报查收（D-11 + D-20）`view_mode=supervisor`**：到达督办人设定 DDL 时推送，替代原「Teable 筛选视图链接」方案，**只做数据交互、不做审核**。已填报项明细**可修改**（预填最新跟进记录），含「龙小督润色」，进度评价可改评（留痕 D-6）；「提交（保存到 Teable）」→ BFF 用督办人托管 Token 写跟进记录表（创建人=督办人）→ 主表自动化同步 → 卡片回执「已保存」；**逾期未填报项**五字段可**代录补正**、可「催办」（T3 项）；**逾期（状态1）项**同样可「催办」（T8 项）。**完结不在表单内操作**：上级督办室**线下**同意完结后，督办人在 Teable **手动将状态1 改为完结**（D-22/v0.6，审计留痕）→ 经办人收「事项已完结」通知 → 该项退出本批及后续全部监控（不再被督办）；不同意完结或暂缓的，督办人在 Teable **回改截止时间**（延期），状态1 按新锚点重置。「**导出 Excel**」→ BFF 生成本批 Excel（编号/名称/五字段/进度评价/状态）→ 导出成功后**龙小督以文件消息发送至本会话**（可点击下载）。督办人**导出 Excel** 即触发**本轮批次关闭**（已填报→暂存，T5，D-21 触发不变）；逾期未填报项保持原状态留痕，下轮启动回推进中（T6）；保存不触发关闭。
- 点「催办」（手动入口，供督办人主动再催；**自动催办路径无需人工点击**，D-15）→ BFF 立即向经办人发 IM + 邮箱通知（邮件通道 1.4.1 前未就绪则先 IM，就绪后补渠道配置）→ 主表「已催办时间」留痕 → 表单内显示催办成功提示 + postMessage `remind`。

### 3.4 24h 填报监督（D-1）

- BFF 定时任务：任务下发（或上次填报批次结束）24h 后，检查经办人是否对批次内所有事项完成五字段提交。
- 未填齐 → 龙小督在对应话题提醒经办人（计入每日催办类 ≤2 条频控，D-7），并同步告知督办人未填清单。

### 3.5 表单状态持久化（D-12）

- 表单状态（已填内容、暂存稿、k/N 位置、已提交/已转办标记）**服务端持久化**，键 = `(batch_id, 填报人 IM 身份)`；客户端不依赖 localStorage。
- session 内任意操作——切换会话、重进聊天窗口、刷新、客户端重启——**再次回到聊天窗口表单仍在**，现场完整恢复；直至整个批次提交完成（卡片置完成态）或用户主动关闭卡片（`closed` 回执，状态保留 7 天后归档）。
- 并发：同一表单多端打开时，服务端以批次+用户维度加乐观锁（版本号），后保存者收到冲突提示并刷新查看最新状态。

### 3.6 提交存档消息（D-12）

- 单项提交成功后：该项表单转为**只读存档**（不可再次打开编辑），仅可查看。
- 同时以**填报人身份**在其聊天 session 生成一条**提交存档消息**（`supervision_archive_card`）：事项编号/名称 + 五字段摘要（落实/困难/下一步/预计完成时间/进度评价）+ 提交时间，与跟进记录表内容一致，作为历史消息供回顾与审计。
- 全部完成 → 批次卡片完成态 + agent 汇总回执（话术见 `agent-scenario-script.md` 第二幕）。

## 4. 提交链路

```
提交第k项 → POST /form/bch_xxx/submit（签名校验）
  → BFF 取填报人托管 Teable Token → 跟进记录表新建记录（link + 五字段）
  → BFF 操作日志 → 200 → postMessage submitted → 卡片角标 + 表单 ✓
转办 → POST /form/bch_xxx/transfer → 校验链路级别（≤次级转办人）→ 写主表转办字段 → 通知新执行人 → transferred 回执
督办人保存（supervisor） → POST /form/bch_xxx/save → 写跟进记录表（创建人=督办人，改评留痕 D-6）
草稿/现场 → POST /form/bch_xxx/draft（每次暂存/字段变更防抖上报，服务端持久化 D-12）
提交成功 → BFF 代填报人发「提交存档消息」入聊天历史（**以用户消息身份发送**，算作用户发送的一次聊内表单消息；点击该消息 → 打开同批次只读表单回看当时提交内容，D-12/D-20）
导出 Excel → POST /form/bch_xxx/export（仅 supervisor）→ BFF 汇总本批（编号/名称/五字段/进度评价/状态）生成 .xlsx → 龙小督以**文件消息**发送至督办人会话（D-20）
Teable 自动化（BFF 不参与）：跟进记录新增/更新 → 最新一条同步主表三反馈字段
```

- **幂等**：`(batch_id, task_no, 填报人, 当日)` 去重；转办/导出同键去重。
- **部分失败**：失败项标红可重试，不影响其他项；草稿服务端保留。

## 5. 安全清单

- [ ] 表单 URL 一次性签名（≤24h），不落 localStorage；身份由 BFF 按 IM 登录态映射，禁止 URL 改身份。
- [ ] 用户 Teable Token 服务端托管（S-3：最小权限、可轮换、加密存储），前端永不见 Token。
- [ ] iframe 白名单仅 BFF 表单域；`frame-ancestors` 限定 IM 域；postMessage 双向校验 origin。
- [ ] 润色服务仅作建议，不落库直到用户确认；润色请求与结果留痕。
- [ ] 进度评价每次修改留痕（谁/何时/改前改后，D-6）；转办/催办/导出/保存全量审计日志。
- [ ] 表单状态持久化存储按身份隔离（仅本人+督办人可见）；提交存档消息以用户本人身份发送，内容不可篡改。

## 6. 降级与二期

| 场景 | 行为 |
|------|------|
| iframe 加载失败/超时 8s | 降级链接卡片新窗口打开同一 form_url（k/N 与批量操作一致） |
| 签名过期/伪造 | 失效提示 + 「重新获取表单」（触发 agent 重发） |
| 早期移动端（二期前） | 链接卡片新窗口；二期响应式 + WebView 直填 |

## 7. 验收
