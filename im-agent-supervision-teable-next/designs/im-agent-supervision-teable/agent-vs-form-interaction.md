## 1. 问题

> 经办人与龙小督的所有交互都回归到系统页面（表单），而非自然语言。龙小督退化为消息通知渠道，不再是灵活的数字员工；基于 Teable 的数据表、回调逻辑（尤其审核功能）在流程 IT 形态下可能不适用。

## 2. 风险分析（承认问题真实存在）

| # | 风险 | 表现 |
|---|------|------|
| P-1 | 交互单通道化 | 经办人学会「等表单、填表单」，不再对龙小督说话 → agent 的智能（理解、澄清、润色、代填、追问）失去用武之地 |
| P-2 | 流程刚性 | 状态机 + 固定表单 = 传统 OA 流转；异常路径（部分填报、口头说明、跨事项合并汇报）难以表达 |
| P-3 | Teable 错位 | 用表格自动化承载分支流程（T1/T2/DDL 判定、批次关闭、重估预警态）超出 Teable 自动化舒适区，硬编脆弱 |

## 3. 设计立场：表单是消息的富媒体载体，不是独立流程入口（建议 D-18）

**龙小督的第一交互是自然语言；表单是龙小督在对话中递出的一块「结构化便签」。** 五条防线：

1. **双通道等价**：表单能做的，自然语言都能做。口头/文字填报 → 龙小督识别 → 润色 → **确认后代填**（AGT-06 已实现，S-1 铁则）；表单只是降低填写成本的快捷键，不是唯一入口。
2. **agent 主动性不变**：触发、预警、加急、升级、审核提醒全部由龙小督主动发起并解释（「为什么现在要填」）；用户任何时刻可用自然语言追问、申请延期、说明困难、讨价还价——这些不进状态机的自由对话由 agent 理解后转化为受控动作（确认后执行）。
3. **无审核环节（D-20）**：聊内弹窗不做审核/打回——DDL 后督办人在查收表单**直接修改数据并提交（保存 Teable）**，可导出 Excel、可催逾期项；不建任何审核系统/审核待办页面。本轮关闭由批次关闭动作触发，状态写回主表。
4. **状态机归 BFF/agent，Teable 归记录**：T1/T2/DDL 判定、批次关闭推进是**代码逻辑**（BFF 定时任务 + agent），状态写回主表单选字段；Teable 自动化只做无分支的数据同步（最新跟进记录→主表三反馈）。Teable 是 system of record，不是流程引擎——**状态机的引入恰恰说明流程逻辑不能塞进表格自动化**，这是本次设计对 P-3 的回答。
5. **表单本身长在会话里**：聊内 iframe 卡片、提交即存档消息、会话内状态持久化（D-12）——表单从不离开对话上下文，用户始终知道「我在和龙小督打交道」，而不是「我在用一个系统」。

## 4. 对「审核功能」的直接回答（D-20 后：不存在审核）

- **PM 决策 D-20：聊内不做审核**。原「审核不流程 IT 化」的顾虑以釜底抽薪方式解决——没有审核环节，就没有流程 IT 化审核。
- 督办人对数据的把控通过**直接修改 + 保存留痕**实现（改评留痕 D-6），对进度的把控通过**催办（逾期项）+ 下一轮启动**实现；不再存在「通过/打回」状态分支。
- 因此 Teable 只需存：状态1（4 值单选：正常/风险/逾期/完结）、状态2（4 值单选：暂存/推进中/已填报/逾期未填报）、跟进记录（含督办人修改记录）、督办DDL/截止时间字段。回调逻辑（何时催、催谁、升级谁、何时关批、状态1 时间计算与完结锁定）在 BFF/agent。
