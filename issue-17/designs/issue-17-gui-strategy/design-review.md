# Issue #17 设计评审：AI-Native 数字员工 GUI 层策略

## 一、核心命题

> 在保留 **Teable 为数据底座、龙小督为功能主入口** 的前提下，为人类用户补充一个友好的 GUI 层，使 EAIC 对外呈现为完整产品，对内仍保持 AI-Native 的灵活性与扩展性。

## 二、假设验证矩阵

| 假设 | 评估 | 证据等级 | 关键论据 |
|------|------|----------|----------|
| **H1：多维表格可在 AI-Native 时代替代传统业务系统** | **可能，但需分阶段** | 中 | 多维表格 = 结构化数据 + 视图 + 权限 + 自动化，本质上是“无代码数据库”。在数据模型简单、流程标准化的场景（督办、任务、审批）中，可以替代轻量级业务系统。复杂场景（ERP、财务、生产）仍需专业系统。 |
| **H2：AI 成为功能首要入口** | **在协作/任务型场景中高可能** | 中高 | Mattermost/IM 是用户高频触点；Bot 能主动推送、 reminders、采集数据。对于查询、填报、简单审批，AI 入口更高效。对于复杂数据分析、批量操作，GUI 仍是必要补充。 |
| **H3：普及 Teable 提升 AI-Native 文化与组织能力** | **长期成立，短期需教育成本** | 中 | 当业务人员能自己建表、设权限、写自动化，他们就具备了“用数据驱动业务”的能力。但短期需要培训、模板、最佳实践，否则会变成“Excel 替代品”而非“AI-Native 底座”。 |
| **H4：提供底层设施被接收后真正带来技术平权** | **取决于易用性与生态成熟度** | 中低 | 技术平权的条件是“非技术人员能独立完成 80% 需求”。Teable 的表单、视图、自动化已经降低门槛，但复杂公式、权限矩阵、API 集成仍有学习曲线。需要配套模板市场和 AI 辅助（如自然语言建表）才能放大平权效应。 |

## 三、论述架构

### 3.1 背景：我们已走到哪里

- EAIC 已集成 Mattermost + Teable，推出数字员工“龙小督”。
- 龙小督在 IM 中接收口头/文本指令，通过 Teable skills 操作督办数据。
- 人类与龙小督围绕 Teable 多维表格协作，数据、权限、自动化都沉淀在 Teable 中。

### 3.2 冲突：领导的预期与当前实现的差距

- **领导的预期**：一个完整的“督办产品”——有清晰的入口、友好的界面、符合业务认知的交互。
- **当前的实现**：用户直接面对 Teable 多维表格，看到的是字段、视图、筛选器，更像数据库工具而非业务应用。
- **根因**：Teable 是通用多维表格平台，不是为“督办”场景量身定制的 GUI。

### 3.3 理念：为什么仍要坚持 AI-Native 路线

1. **数据模型即业务规则**：多维表格让业务人员能自己定义字段、关系、权限，不再依赖研发排期。
2. **AI 让自然语言成为操作界面**：用户用口语描述需求，AI 翻译成对数据的操作。
3. **组织能力的沉淀**：每个业务场景的可复用组件（表模板、自动化、Bot 技能）都会积累成组织资产。
4. **长期成本更低**：避免为每个小场景单独开发一套系统。

### 3.4 折中策略：三层架构

```
┌─────────────────────────────────────────────────────────┐
│  人类用户层                                               │
│  - IM 中的龙小督（AI 入口，首要）                         │
│  - 友好的 GUI 层（人类补充，用于展示/填报/审批）           │
└─────────────────────────────────────────────────────────┘
                            │
┌─────────────────────────────────────────────────────────┐
│  AI 操作系统层：Teable 多维表格                           │
│  - 数据模型、权限、视图、自动化                            │
│  - 所有业务数据的唯一事实来源                              │
└─────────────────────────────────────────────────────────┘
                            │
┌─────────────────────────────────────────────────────────┐
│  基础设施层                                               │
│  - Mattermost（IM 与 Bot 平台）                           │
│  - Teable API / Embed / Share View                        │
└─────────────────────────────────────────────────────────┘
```

**关键结论**：GUI 层不是替代 Teable，而是 Teable 的“人类友好皮肤”；龙小督不是替代 GUI，而是“高效触发器”。

### 3.5 实施路径

1. **短期（1-2 个月）**：
   - 在 Mattermost 消息中嵌入自研 iframe 表单，支持多表单翻页与用户令牌提交。
   - 建设最小 GUI 看板：督办列表、进度、详情、跳转入口。
   - 用现有 Teable API + Mattermost Bot 框架实现，不引入新后端。

2. **中期（3-6 个月）**：
   - 完善 GUI 层：看板、日历、审批流、通知中心。
   - 建立业务模板库：督办、任务、审批等场景的 Teable Base 模板。
   - 引入 AI 辅助建表：用户用自然语言描述业务，AI 生成表结构。

3. **长期（6-12 个月）**：
   - 推广 AI-Native 工作方式：业务人员自主搭建场景。
   - 沉淀组织知识库：把成功案例、模板、技能沉淀到 Obsidian/Knowledge。
   - 评估是否需要自研更重的“应用构建器”或继续依赖 Teable 的 App Builder。

### 3.6 风险与前提

| 风险 | 等级 | 应对 |
|------|------|------|
| 领导对“Teable 为底座”仍不认可 | 高 | 短期用 GUI 层补齐体验，长期用数据和案例证明底座价值 |
| 用户在 IM 中填表体验不佳 | 中 | 提供“跳转到完整页面”备选；表单字段精简、分页合理 |
| Teable API/权限变化导致集成失效 | 中 | 封装 Teable 适配层，避免业务代码直接依赖 API 细节 |
| 自研 iframe 表单的安全与跨域问题 | 中 | 使用 postMessage 通信；提交时使用用户 token；配置 CSP |
| AI-Native 推广需要组织变革 | 高 | 分阶段培训，先从高频小场景切入，建立早期成功案例 |

## 四、推荐方案

### 4.1 表单填报：自研 iframe 嵌入 Mattermost

- **不强制使用 Teable 原生 form view**，而是开发一个独立 iframe 页面。
- 该页面通过 Teable API 读取该经办人待填报的多条数据。
- 每条数据渲染为一个表单页面，支持翻页。
- 提交时携带用户身份令牌，确保操作痕迹归属正确。
- 技术路径：Mattermost custom post type + Web App plugin + 自研表单前端 + Teable API。

### 4.2 数据看板：独立 GUI 页面

- 通过 Teable API 读取督办数据。
- 提供看板、列表、甘特图等视图。
- 从 Mattermost 侧边栏或龙小督消息中打开。

### 4.3 龙小督的角色

- **编排者**：理解用户意图，决定调用 GUI 看板、iframe 表单还是直接回答。
- **数据操作员**：通过 Teable skills/API 读写数据。
- **上下文管理者**：维护话题、计划、待办等状态（未来扩展）。

## 五、关键决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 表单视图来源 | **自研 iframe 表单** | 用户明确反馈；更灵活，支持翻页、用户令牌、自定义样式 |
| 嵌入方式 | **Mattermost custom post type** | 官方推荐；比直接 iframe 嵌入 Mattermost 应用更安全 |
| 数据底座 | **保持 Teable** | 不破坏现有架构；Teable 的权限、视图、自动化已验证可用 |
| GUI 层技术栈 | **先轻量 Web 前端** | 用现有 Teable API；避免引入新后端；后续可演进为 App Builder 应用 |

## 六、 success criteria

1. 领导能理解并接受“Teable 底座 + AI 入口 + GUI 补充”的三层架构。
2. Mattermost 消息中可嵌入自研 iframe 表单，并演示多表单翻页与提交。
3. 技术调研覆盖 Mattermost v10/v11 与 Teable 2026 最新特性，明确可直接使用的能力。
4. 下一阶段有清晰的 TDD 研发计划与任务拆分。
