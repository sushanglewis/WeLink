# Issue #17 场景文档

## 场景 1：领导查看产品形态

**角色**：领导
**触发**：周会/汇报时打开 EAIC 产品
**流程**：
1. 领导点击 Mattermost 侧边栏的“督办看板”入口。
2. 浏览器打开 GUI 层页面，展示督办列表、完成率、逾期预警。
3. 页面视觉符合业务认知，不像多维表格工具。
4. 领导点头，认为这是一个完整产品。

**价值**：对外展示完整产品形态，提升领导信心。

## 场景 2：经办人在 IM 中批量填报

**角色**：业务用户（经办人）
**触发**：龙小督提醒“您有 3 条待填报督办项”
**流程**：
1. 龙小督在 Mattermost 中发送一条消息，内嵌 iframe 表单。
2. 经办人看到第 1 条待填报数据，填写后点击“提交并下一条”。
3. iframe 内翻页到第 2 条，继续填写。
4. 全部提交后，iframe 显示完成摘要，龙小督回复确认。

**价值**：无需跳转多个系统，在 IM 内完成批量填报。

## 场景 3：业务人员查询督办进度

**角色**：业务用户
**触发**：用户问龙小督“我的督办进度如何？”
**流程**：
1. 龙小督理解意图，返回文字摘要 + 一个 GUI 看板链接。
2. 用户点击链接，打开 GUI 看板，查看详情。
3. 用户可在看板中筛选、排序、导出。

**价值**：AI 入口快速响应，GUI 提供复杂数据查看能力。

## 场景 4：龙小督主动催办

**角色**：数字员工 / 龙小督
**触发**：Teable 自动化检测到某项督办即将逾期
**流程**：
1. Teable 自动化触发 webhook 到龙小督。
2. 龙小督在 Mattermost 中 @ 相关负责人，发送 iframe 表单或看板链接。
3. 负责人直接在消息内处理。

**价值**：主动、及时、闭环。

## 场景 5：管理员配置新督办场景

**角色**：业务管理员
**触发**：新业务需要督办
**流程**：
1. 管理员复制 Teable Base 模板。
2. 用自然语言或可视化方式调整字段、权限、自动化。
3. 告诉龙小督新业务规则。
4. 龙小督即可为新场景提供服务，GUI 层自动适配数据模型。

**价值**：业务人员自主扩展，技术平权。
