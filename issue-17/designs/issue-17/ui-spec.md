# UI 规格: issue-17

> 本规格基于已批准的 `design-review.md` 与 `feature-catalog.md`，为 HTML 原型与后续实现提供界面/交互依据。

## 设计原则

1. **IM 窗口即工作台**：所有能力扩展在现有数字员工聊天窗口内完成，不另开落地页。
2. **桌面优先**：主要承载为 Tauri/WebView 桌面端，B/S 端保持一致布局。
3. **对话内轻交互**：话题、Clarify、Plan、胶囊均在消息层以卡片/选项卡/菜单形式呈现。
4. ** iframe 嵌入复用**：日程看板、Teable 表单通过受控 iframe 嵌入，保持原产品样式。

## 整体布局

```
+------------------------------------------+
| 数字员工 IM 工作台                        |
+------------------+-----------------------+
| 话题列表          | 消息区域               |
| · 新建话题       | · 历史消息             |
| · 历史话题       | · Plan/Clarify/胶囊卡片 |
|                  | · Clarify 底部选项卡   |
+------------------+-----------------------+
| + | 输入框       | 发送                  |
+------------------------------------------+
```

## 各区域规格

### 1. 话题侧边栏

- 宽度：220px，左侧固定。
- 元素：
  - 标题「话题列表」
  - 话题项：标题 + 最后活跃时间/消息数
  - 当前话题高亮（左侧蓝色竖条 + 浅蓝背景）
  - 「+ 新建话题」按钮（虚线边框）
- 交互：点击切换话题；新建话题创建新 Mattermost thread。

### 2. 消息区域

- 占据剩余宽度；消息按 thread 隔离。
- 消息气泡：用户（右侧浅蓝），Agent（左侧灰底）。
- 特殊消息卡片：
  - **Plan 卡片**：白色卡片，展示 markdown 渲染的计划（背景/目标/步骤/依赖/验收标准/风险），底部「通过」「需要修改」按钮。
  - **胶囊消息**：消息内嵌胶囊标签（skill / MCP / 插件 / Teable），可点击展开元信息。
  - **Teable 表单消息**：卡片内含 iframe 占位，下方显示提交结果。

### 3. Clarify 底部选项卡

- 触发：Agent 调用 Clarify 工具时，在输入栏上方弹出。
- 结构：问题文案 + 3 个推荐选项 + 1 个自定义输入 + 提交按钮。
- 交互：点击选项或填写自定义后提交，以 user message 回传。

### 4. 输入栏

- 高度：约 56px，底部固定。
- 元素：
  - 「+」胶囊选择按钮（圆形）
  - 文本输入框（圆角）
  - 「发送」按钮
- 点击「+」弹出四层/四列胶囊选择面板（Skills / MCP / 插件 / 多维表格）。

### 5. 日程看板

- 入口：侧边栏或聊天内按钮。
- 形态：新页面或右侧抽屉，iframe 嵌入开源日历 UI。
- 视图：月/周/日切换工具栏 + 事件列表侧边栏。

### 6. Token 管理界面

- 表单：授权对象、权限范围、后端类型。
- 列表：Token ID、授权对象、权限、签发时间、撤销按钮。

## 交互规则

- 话题切换：不丢失上下文；新消息归属当前 thread。
- Plan 审批：未点击「通过」前，Agent 不执行关键动作；修改意见驱动 Plan.md 版本递增。
- Clarify：可多轮，每轮生成新的 ClarifySession round。
- 胶囊：仅展示用户/Agent 有权限的对象；非法 schema 显示「无法解析」。
- 日程：Agent 代用户创建事件；多人事件所有参与人可见；Agent 自身事件可触发 Agent 动作。
