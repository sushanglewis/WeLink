## 非功能需求

- **个人日程范围**：用户仅关注个人日程；多人事件所有参与人均可见；不与 Outlook/Google 日历互通（对齐 PRD）。
- **性能**：话题切换、Clarify 弹窗、Plan 卡片渲染前端响应 < 500ms；日程看板 iframe 首屏 < 3s；工作台首页首屏 < 2s。
- **安全**：iframe 启用 HTTPS、CSP、postMessage 白名单；token 不硬编码、可轮换、权限最小化；胶囊仅展示用户有权限的对象；日程操作按 token 权限收敛；工资条场景强制水印与操作审计。
- **权限架构**：数字员工平台侧仅维护系统级访问清单；数据权限分散到各业务系统（对齐 9/2 会议纪要）。
- **兼容性**：桌面端（Tauri/WebView）与 B/S 端表现一致；日程看板仅需 Web/iframe 可用，不要求移动端原生 SDK。
- **License 合规**：日程后端限定 MIT / Apache-2.0 / AGPL，排除 GPL 家族；最终选型经 PoC 与合规评审确认。
- **Agent 友好**：日历后端提供 CLI / REST API / MCP server / JMAP 至少一种可编程接口；agent 侧统一封装为 skill / MCP server / CLI，后端可替换。
- **国产化**：优先国内可部署或有商业买断路径的方案，遵循 issue-3/6/11/14 的国产化约束。
- **数据**：业务数据最终统一对接企业主数据系统（1.6.1 起，对齐 9/2 会议纪要）。
