# 子需求：组织化数字员工管理（P0 / 1.4.0）

<!-- status: draft -->

## 背景与来源

本文件从 issue-17 综合需求中拆分而出，聚焦「数字员工像正式员工一样融入企业组织」这一 2026-09-02 领导会议纪要新增能力。

- **来源 Issue**: [WeLink #17](https://github.com/sushanglewis/WeLink/issues/17)
- **来源会议纪要**: `issue-17/interviews/2026-09-02-roadmap-meeting/summary.md`（2026-09-02）
- **上游 PRD**: `issue-17/requirements/2026-08-24-issue-17/prd.md`
- **上游需求文档**: `issue-17/requirements/2026-08-24-issue-17/requirements.md`
- **关联**: issue-14（数字员工平台，运行时与 Mattermost 底座）
- **目标版本**: 1.4.0（10 月上）

会议纪要原始论述：

> 「数字员工的创建和产生：业务部门提需求（需要什么样的经验、画像），人力资源部帮他做基础配置，然后把它纳入企业通讯录，数字赋能部配置账号、配置权限、配置岗位职责。」

> 「数字员工定位为企业内的初级岗位员工，优先处理登记、分发、归集这类无需复杂判断的基础事务，暂不追求全知全能。」

> 「数字员工的创建不能由单个用户随意操作，避免短时间内生成 50 个以上的冗余 Agent，造成组织内数字员工体系混乱。」

> 「大部分的权限是在系统里，不是在数字员工身上……我们只能跟他说你能不能访问这个系统，他能访问这个系统，在系统里每个系统会管理他的访问权限。你要在这里统一管理就非常复杂。」

## 目标

1. **规范创建流程**：数字员工的创建必须经过「业务部门提需求 → HR 基础配置 → 纳入企业通讯录 → 数字赋能部配置」的审批流，杜绝随意创建。
2. **融入组织体系**：数字员工作为企业通讯录的组成部分，与人类员工在同一体系下管理，有明确的部门、岗位与职责。
3. **初级岗位定位**：数字员工优先承担登记、分发、归集等基础事务，能力边界清晰，不追求全能 Agent。
4. **权限分散管理**：平台侧仅控制数字员工「能访问哪些系统」；系统内数据权限由各业务系统自行管理；仅人事岗位开放技能配置权限。
5. **降低使用门槛**：参考飞书 Agent 打包预设权限的经验，将常用能力打包为预设配置，降低业务侧使用与配置成本。

## 范围（In Scope）

### O-1 创建审批流

- **提交需求**：业务部门负责人提交数字员工创建需求，包含：岗位名称、职责描述、能力画像（参考「招聘画像」：需要什么经验、处理什么事务）、预期使用范围。
- **HR 基础配置**：人力资源部审核需求，完成基础信息配置（姓名、部门、岗位、汇报关系），将其纳入企业通讯录。
- **数字赋能部配置**：数字赋能部完成技术配置：账号开通、系统访问范围（能访问哪些系统）、岗位职责（skills/工具集）、运行参数。
- **审批状态机**：草稿 → 已提交 → HR 审核中 → HR 通过（已入通讯录）→ 赋能部配置中 → 已上岗 → （可停用/注销）。
- 每一步操作留痕（操作人、时间、变更内容），全程可追溯。

### O-2 通讯录纳入

- 数字员工纳入企业通讯录，与人类员工同体系展示：头像、姓名、部门、岗位。
- 通讯录中标识其为数字员工（如「数字员工」标签），可被检索、可被 @、可加入群组与频道。
- 数字员工离职（停用/注销）流程与人类员工一致：从通讯录移除或标记停用，其历史操作记录保留审计。

### O-3 岗位职责与能力边界

- 每个数字员工有明确的岗位职责描述（登记、分发、归集等基础事务优先）。
- 岗位说明书中约定：不追求全知全能；超出职责范围的请求应礼貌拒绝或转交对应数字员工/人类。
- 能力边界在配置时由数字赋能部设定，运行中受权限与工具集约束。

### O-4 权限分散管理

- **平台侧权限**：仅维护「系统级访问清单」——数字员工能访问哪些业务系统（如 Teable、OA、邮件系统）。
- **业务系统侧权限**：各业务系统内部管理数据级权限（能看哪些表、哪些数据行），数字员工平台不重复建设统一数据权限。
- **技能配置权限**：仅人事岗位拥有技能配置权限；业务侧可在授权范围内灵活配置数字员工可访问的业务范围。
- **预设权限包**：参考飞书 Agent 经验，为常见岗位提供打包好的预设权限包，降低配置门槛。

### O-5 防冗余与生命周期治理

- 普通用户无创建入口；创建必须走 O-1 审批流（系统层面强制）。
- 提供数字员工台账：全员可见在职数字员工列表（名称、部门、岗位、负责人、创建时间）。
- 定期盘点机制：支持按活跃度输出冗余预警（如长期无使用、职责重叠的数字员工清单），供数字赋能部治理决策。
- 生命周期：上岗、转岗（变更职责/权限）、停用、注销四态，均走审批并留痕。

## 非目标

- 不建设通用统一权限平台；数据权限分散到业务系统是既定原则，本文件不设计各业务系统内部权限模型。
- 不替代各业务系统自身的账号体系；数字员工在各业务系统内的账号映射由对应系统管理。
- 不做数字员工能力市场/自由创建（与纪要「禁止随意创建」冲突）。
- 数字员工运行底座（OpenClaw + Mattermost）本身属 issue-14，本文件只用其能力。

## 用户故事

### 故事一：业务部门按流程申请数字员工

- **作为**：业务部门负责人
- **我希望**：提交数字员工创建需求（岗位、职责、能力画像），HR 和数字赋能部依次完成配置后数字员工入岗
- **以便**：数字员工像正式员工一样有规范的入职流程与明确职责
- **验收标准**：
  - 创建需求表单包含岗位名称、职责描述、能力画像、使用范围。
  - 审批流按 业务部门 → HR → 数字赋能部 顺序流转，状态可见。
  - 全部步骤操作留痕。

### 故事二：在通讯录中找到数字员工

- **作为**：企业内部员工
- **我希望**：在企业通讯录中看到数字员工，能分辨其数字员工身份，能 @ 它或发起对话
- **以便**：数字员工成为组织协作的自然组成部分
- **验收标准**：
  - 数字员工出现在通讯录，带「数字员工」标识。
  - 可被检索、@、加入群组与频道。
  - 停用/注销后按流程移除并保留审计记录。

### 故事三：人事配置数字员工技能

- **作为**：人事岗位
- **我希望**：为已上岗的数字员工配置技能与可访问的业务范围，使用预设权限包快速完成
- **以便**：业务侧灵活配置且门槛可控
- **验收标准**：
  - 仅人事岗位有技能配置入口与权限。
  - 提供岗位预设权限包，可一键应用后微调。
  - 系统级访问范围（能访问哪些系统）由数字赋能部配置。

### 故事四：治理冗余数字员工

- **作为**：数字赋能部
- **我希望**：查看全部在职数字员工台账与活跃度预警，对冗余/停用数字员工执行治理
- **以便**：组织内数字员工体系长期健康，不出现 50+ 冗余 Agent
- **验收标准**：
  - 普通用户无法自行创建数字员工。
  - 台账展示名称、部门、岗位、负责人、创建时间与活跃度。
  - 支持停用/注销审批与历史审计。

## 验收标准

### 创建与审批

- [ ] 创建需求表单包含岗位名称、职责描述、能力画像、使用范围四要素。
- [ ] 审批流按既定顺序流转，每步状态对申请人可见。
- [ ] 普通用户无创建入口，无法绕过审批流。
- [ ] 全流程操作留痕可查。

### 通讯录与岗位

- [ ] 数字员工出现在企业通讯录并带「数字员工」标识。
- [ ] 可被检索、@、加入群组与频道。
- [ ] 每个数字员工有岗位说明书，超范围请求按约定拒绝或转交。
- [ ] 停用/注销按流程执行，历史操作记录保留审计。

### 权限与治理

- [ ] 平台侧仅配置系统级访问清单，不建设统一数据权限。
- [ ] 仅人事岗位拥有技能配置权限。
- [ ] 提供至少 2 个岗位预设权限包。
- [ ] 台账可输出活跃度预警清单。
- [ ] 系统层面不存在单个用户随意创建数字员工的途径。

## 数据模型

复用 `issue-17/designs/issue-17/fields.md` 中 Agent/Account 相关模型，新增/扩展以下概念（详细字段在设计阶段定稿）：

| 概念 | 说明 |
|------|------|
| AgentProfile | 数字员工档案：agent_id、姓名、部门、岗位、岗位说明书、状态（上岗/转岗/停用/注销）、负责人 |
| CreationRequest | 创建申请：申请部门、岗位名称、职责描述、能力画像、使用范围、审批状态机 |
| ApprovalRecord | 审批记录：步骤、操作人、时间、变更内容、意见 |
| SystemAccessGrant | 系统级访问授权：agent_id、目标系统、授权范围、授权人、有效期 |
| SkillConfig | 技能配置（仅人事可改）：agent_id、技能集、业务范围、预设包引用 |
| AgentDirectoryEntry | 通讯录条目：与 AgentProfile 关联，含数字员工标识、检索标签 |

## 界面/交互说明

- **管理端入口**：创建申请、审批流、台账、技能配置集中在数字员工管理端（可复用工作台导航，管理端形态在 ui-spec 阶段细化）。
- **通讯录展示**：头像 + 姓名 + 「数字员工」标签 + 部门/岗位；详情页展示岗位说明书与负责人。
- **审批通知**：审批流转通过 IM 通知当前处理人（复用数字员工 IM 的通知机制）。
- 管理端/企业管理端的大框架属九月计划背景条目，本文件仅约束数字员工管理所需最小界面。
