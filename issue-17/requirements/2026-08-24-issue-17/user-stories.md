# 用户故事: 2026-08-24-issue-17

## 用户故事一：创建话题以开始新任务

- **作为**：企业内部员工
- **我希望**：在与数字员工的聊天窗口中创建一个新话题
- **以便**：围绕一个新任务开始独立讨论，而不混入当前对话上下文
- **验收标准**：
  - 聊天界面提供「新建话题」入口。
  - 创建后自动进入新话题窗口，历史消息为空或仅显示系统提示。
  - 新话题在话题列表中可见，包含标题和创建时间。

## 用户故事二：切换并继续历史话题

- **作为**：企业内部员工
- **我希望**：在话题列表中点击一个历史话题
- **以便**：查看该话题的历史对话并继续讨论
- **验收标准**：
  - 话题列表展示所有历史话题及最后活跃时间。
  - 点击话题后，聊天窗口加载该话题的全部历史消息。
  - 继续发送的消息归属到该话题，不影响其他话题。

## 用户故事三：Agent 主动创建话题

- **作为**：数字员工（agent）
- **我希望**：当用户提出一个与当前话题明显不同的新任务时，主动建议或创建新话题
- **以便**：将不同任务隔离到不同上下文，提高协作效率
- **验收标准**：
  - Agent 可在对话中提示用户「是否创建新话题讨论 X」。
  - 用户确认后创建新话题并迁移上下文；agent 也可在特定规则下自动创建。
  - 新话题自动携带必要的上下文摘要（可选）。

## 用户故事四：通过 Clarify 澄清模糊需求

- **作为**：企业内部员工
- **我希望**：当我的需求不够明确时，agent 以底部弹窗列出多个选项供我选择
- **以便**：快速澄清意图，减少反复沟通
- **验收标准**：
  - 每个问题提供 3 个推荐选项 + 1 个自定义输入框。
  - 我可以单选或多选（视问题类型而定）。
  - 提交后，我的选择以 user message 形式发送给 agent。
  - 支持多轮 Clarify。

## 用户故事五：审阅并批准 Agent 的执行计划

- **作为**：企业内部员工
- **我希望**：对于复杂任务，agent 先生成 Plan.md 供我审阅
- **以便**：了解任务前因后果、步骤和风险，确认后再执行
- **验收标准**：
  - Plan.md 以 markdown 消息卡片展示，包含背景、目标、步骤、依赖、验收标准、风险。
  - 卡片提供「通过」和「需要修改」按钮。
  - 我可以在输入框描述修改意见，agent 据此更新 Plan.md。
  - Plan 通过前，agent 不执行关键动作；通过后按 Plan 执行。

## 用户故事六：在消息中插入 Teable 表格胶囊

- **作为**：企业内部员工
- **我希望**：在输入框点击「+」并选择我的 teable 表格
- **以便**：以胶囊形式将表格关键信息插入消息，让 agent 操作表格数据
- **验收标准**：
  - 「+」菜单提供「多维表格 → 多维表格控件 → 数据库 → 多维表」四级选择。
  - 仅展示我有权限的表格。
  - 插入的胶囊显示表名等可读信息，并携带 base_id / table_id / view_id。
  - Agent 可解析胶囊并调用 teable skills。

## 用户故事七：在聊天中填写并提交 Teable 表单

- **作为**：企业内部员工
- **我希望**：Agent 发送的 teable 表单以 iframe 嵌入消息
- **以便**：我无需离开聊天窗口即可填报数据
- **验收标准**：
  - 表单 iframe 保持 teable 原样式。
  - 我可以在 iframe 中填写字段并提交。
  - 提交后数据同步到 teable，并在聊天中显示提交成功/失败提示。
  - iframe 权限受控，仅允许访问指定 teable 域名。

## 用户故事八：Agent 从对话中创建日程

- **作为**：企业内部员工
- **我希望**：当对话中产生待办事项时，agent 自动为我创建日程
- **以便**：待办落入个人日程看板，避免遗漏
- **验收标准**：
  - Agent 识别对话中的时间、事项、参与人信息。
  - Agent 调用日历后端创建事件并返回确认信息。
  - 事件出现在我的日程看板中。

## 用户故事九：邀请成员加入日程

- **作为**：企业内部员工
- **我希望**：Agent 创建日程时可以将其他成员加入并发送邀请
- **以便**：相关同事收到通知并能在自己的看板中看到事件
- **验收标准**：
  - Agent 可通过用户名/邮箱添加参与人。
  - 受邀人收到通知（IM 消息或邮件，视后端能力而定）。
  - 受邀人在其日程看板中可见该事件（至少为共享/受邀视图）。

## 用户故事十：查看个人日程看板

- **作为**：企业内部员工
- **我希望**：在 WeLink 中打开我的日程看板
- **以便**：查看、编辑、管理我的日程事件
- **验收标准**：
  - 提供日程看板入口（侧边栏或聊天内入口）。
  - 看板通过 iframe 嵌入开源日历 UI，支持月/周/日视图。
  - 我可以在看板中查看、编辑、删除事件。

## 用户故事十一：为 Agent 签发日程访问 Token

- **作为**：企业内部员工 / 管理员
- **我希望**：为 agent 签发访问我日程后端的 token
- **以便**：agent 可以代我创建和管理日程，同时 token 可独立回收
- **验收标准**：
  - Token 签发界面清晰说明权限范围（读写日程、邀请成员）。
  - Token 可独立生成、查看、撤销。
  - Agent 使用 token 调用日历后端 API/CLI/MCP。

## 非功能性验收

- **License 合规**：日程后端必须采用 MIT / Apache-2.0 / AGPL 协议；GPL 家族排除。
- **Agent 友好**：日历后端需提供 CLI、REST API、MCP server 或 JMAP 中至少一种可编程接口。
- **国产化兼容**：优先选择国内可部署或有商业买断路径的开源方案。
- **安全性**：iframe 嵌入启用 HTTPS、CSP、postMessage 白名单；token 不硬编码、可轮换。
