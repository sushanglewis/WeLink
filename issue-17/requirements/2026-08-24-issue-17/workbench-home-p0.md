# 子需求：独立工作台首页（P0 / 1.3.1-1.4.0）

<!-- status: draft -->

## 背景与来源

本文件从 issue-17 综合需求中拆分而出，聚焦「独立工作台首页」这一 2026-09-02 领导会议纪要新增的核心能力。

- **来源 Issue**: [WeLink #17](https://github.com/sushanglewis/WeLink/issues/17)
- **来源会议纪要**: `issue-17/interviews/2026-09-02-roadmap-meeting/summary.md`（2026-09-02）
- **PM 决策（2026-09-03）**: 工作台形态为**独立工作台首页**（默认落地页），数字员工 IM 为对外协同入口
- **上游 PRD**: `issue-17/requirements/2026-08-24-issue-17/prd.md`
- **上游需求文档**: `issue-17/requirements/2026-08-24-issue-17/requirements.md`
- **目标版本**: 1.3.1 首页 MVP（待办 + 督办数据源）；1.4.0 完整版（待办/通知/知识三模块）

会议纪要原始论述：

> 「人在日常工作中本质上只有几件事情：第一，你现在有什么工作，这叫待办……有可能是流程上来审批，有可能是我艾特你的一个什么事情（督办）；第二部分是公司持续产生的信息，有今天的通知；第三个就是你所有的需要工作的技能和知识。」

> 「工作台是我自己工作的地方，它不是用来交流的地方；数字员工是我要让别人干活或者要交流的界面，不要混在一起。」

**决策张力记录**：纪要中另有「工作台入口不得比数字员工更明显」「在 IM 窗口里做工作台能力的改造」的发言。PM 决策为独立工作台首页，本文件按 PM 决策执行；评审时若与领导对齐需要回退为 IM 内嵌形态，首页的信息架构（三模块）可复用。

## 目标

1. **统一工作入口**：工作台首页作为系统默认落地页，员工打开系统即可掌握全天工作，无需在多个系统间切换。
2. **待办聚合**：聚合流程审批事项与他人艾特的督办任务，支持筛选、优先级排序与一键跳转处理。
3. **通知触达**：组织发布的公告、活动、规则等信息流，按相关性与时间排序推送。
4. **知识支撑**：将知识库从组织层面落地到个人工作支撑，聚合与本人工作相关的邮件、文档、文章。
5. **数字员工入口**：首页保留数字员工 IM 协同入口，工作台处理个人工作、数字员工负责对外协同的边界清晰。

## 范围（In Scope）

### W-1 待办模块

- 聚合两类待办：
  - **流程审批**：来自 OA / 业务流程系统的待审批事项（接入范围见 `wework-replacement-p0.md` 与「工作台内部系统接入（EAIC 部署）-OA」依赖）。
  - **督办任务**：他人在督办场景中艾特/指派给我的事项（数据源：龙小督督办台账，见 `supervision-p0.md`）。
- 待办列表展示：标题、来源、发起人、时间要求、当前状态、优先级。
- 支持按来源（审批/督办）、状态（待处理/进行中/已逾期）、时间筛选与排序。
- 点击待办跳转处理：审批跳审批详情页，督办跳对应「批次-事项」话题（见 `topic-windows-p0.md`）。
- 已办事项留存可查（默认展示最近 N 条）。

### W-2 通知模块

- 展示组织发布的公告、活动、规则等通知信息。
- 支持按类型（公告/活动/规则）、已读/未读筛选；未读数角标。
- 通知详情页支持确认已读；重要通知要求强制阅读确认。
- 通知来源：管理端发布（九月计划中的平台管理端/企业管理端条目为依赖系统，不在本文件范围）。

### W-3 知识模块

- 聚合与当前用户工作相关的知识内容：邮件、文档、文章。
- 来源包括但不限于：企业知识库（issue-3 AI 工作台方向）、邮件系统（见 `email-p0.md`）、在线文档（九月计划条目，为背景依赖）。
- 支持按类型、来源、关键词检索；支持「与我相关」智能聚合（基于本人待办与督办上下文推荐相关知识）。
- 解决纪要指出的「过往知识库设计偏向组织层面，未落地到个人工作支撑」问题。

### W-4 数字员工入口

- 首页提供数字员工（含龙小督等）IM 协同入口，点击进入对应数字员工对话窗口。
- 工作台处理个人工作，数字员工负责对外协同、任务分配、跨角色协作，两者边界互不重叠。
- 首页可展示数字员工主动推送的卡片（如督办催办、每日汇总，见 `supervision-p0.md` S-5）。

### W-5 首页框架（1.3.1 MVP）

- 1.3.1 仅交付首页框架 + 待办模块（审批 + 督办数据源）+ 数字员工入口；通知与知识模块占位，1.4.0 完整交付。
- 首页作为系统默认落地页；用户可从首页进入 IM、日程看板（1.7.x）等其他模块。

## 非目标

- 不替换 Mattermost 作为数字员工 IM 底层；工作台首页与 IM 是两个界面，通过入口互通。
- 不建设管理端发布系统（通知发布、知识维护的管理端属九月计划管理端条目，仅作背景依赖）。
- 不在本文件实现审批、考勤、工资条本身（属 `wework-replacement-p0.md`），本文件只负责「待办聚合入口」。
- 不做通用门户/应用市场（AI 门户为纪要后续方向，不进当前版本）。
- 移动端适配不在当前版本（移动端打卡/IM 为九月计划伊莎负责条目，仅作背景）。

## 用户故事

### 故事一：打开首页掌握全天工作

- **作为**：企业内部员工
- **我希望**：打开系统默认落地的工作台首页，看到我的待办、组织通知、与我相关的知识
- **以便**：不用打开多个系统即可规划与处理全天工作
- **验收标准**：
  - 首页含待办、通知、知识三模块（1.3.1 为待办 + 占位）。
  - 待办含流程审批与督办任务，可筛选、可跳转处理。
  - 首页提供数字员工 IM 入口。

### 故事二：从待办直接处理审批与督办

- **作为**：企业内部员工
- **我希望**：点击待办列表中的审批事项跳转到审批详情，点击督办任务跳转到对应督办话题
- **以便**：不待办列表与实际处理场景双向贯通
- **验收标准**：
  - 审批待办跳转 OA 审批详情并可返回首页。
  - 督办待办跳转对应「批次-事项」话题。
  - 处理完成后待办状态同步更新。

### 故事三：接收到与我相关的通知

- **作为**：企业内部员工
- **我希望**：在首页通知模块看到组织公告、活动、规则，重要通知要求确认已读
- **以便**：不错过需要知晓的组织信息
- **验收标准**：
  - 通知按类型与相关性排序，未读有角标。
  - 重要通知支持强制阅读确认。

### 故事四：获取与个人工作相关的知识

- **作为**：企业内部员工
- **我希望**：知识模块聚合与我工作相关的邮件、文档、文章，支持检索与智能推荐
- **以便**：知识库从组织层面落地到个人工作支撑
- **验收标准**：
  - 知识内容按类型/来源/关键词可检索。
  - 支持基于本人待办与督办上下文的「与我相关」聚合。

| 首页框架与默认落地 | 工作台首页作为系统默认落地页，含三模块布局与导航 | P0 | 1.3.1 |
| 待办-流程审批聚合 | 聚合 OA 待审批事项，含筛选/排序/跳转处理 | P0 | 1.3.1 |
| 待办-督办任务聚合 | 聚合督办台账中指派给我的事项，跳转对应话题 | P0 | 1.3.1 |
| 数字员工入口 | 首页进入数字员工 IM 窗口；展示数字员工推送卡片 | P0 | 1.3.1 |
| 通知模块 | 组织公告/活动/规则信息流，类型筛选、未读角标、已读确认 | P0 | 1.4.0 |

## 验收标准

### 首页与待办（1.3.1）

- [ ] 系统默认落地页为工作台首页。
- [ ] 待办模块聚合流程审批与督办任务，展示标题、来源、发起人、时间要求、状态、优先级。
- [ ] 支持按来源、状态、时间筛选与排序。
- [ ] 审批待办跳转审批详情并可回跳；督办待办跳转对应话题。
- [ ] 首页提供数字员工 IM 入口。
- [ ] 首页可展示数字员工推送卡片（催办、汇总报告）。

### 通知与知识（1.4.0）

- [ ] 通知模块展示公告/活动/规则，支持类型筛选、未读角标、已读确认。
- [ ] 重要通知支持强制阅读确认。
- [ ] 知识模块聚合邮件/文档/文章，支持类型、来源、关键词检索。
- [ ] 支持「与我相关」智能聚合。
- [ ] 已办事项与已读通知留存可查。

## 数据模型

复用 `issue-17/designs/issue-17/fields.md` 中既有模型，新增/扩展以下概念（详细字段在设计阶段定稿）：

| 概念 | 说明 |
|------|------|
| TodoItem | 待办项：统一抽象审批与督办两类待办，含 source_type（approval/supervision）、source_id、title、initiator、due_at、status、priority |
| Notice | 通知：type（announcement/activity/rule）、title、body、 publisher、target_scope、require_ack、read_status |
| KnowledgeItem | 知识项：content_type（email/doc/article）、source、title、summary、related_todo 关联 |
| DigestCard | 数字员工推送卡片在首页的展示载体（复用督办 DailyDigest 等） |

## 界面/交互说明

### 首页布局（初稿）

```
+------------------------------------------------------------------+
| 工作台首页（默认落地页）                                            |
+----------+-------------------------------------------------------+
| 导航      | 待办模块                | 通知模块        | 知识模块   |
| · 首页    | ┌ 审批（n）┬ 督办（m）┐  | · 公告列表       | · 推荐    |
| · IM 数字 | │ 筛选/排序  │          │  · 未读角标      | · 检索    |
|   员工    | └ 待办列表（可跳转）┘    │  · 已读确认      │ · 与我相关 |
| · 日程*   |                        |                 |           |
+----------+-------------------------------------------------------+
| 数字员工推送卡片区（催办/汇总/通知）                                  |
+------------------------------------------------------------------+
* 日程为 1.7.x 能力，导航入口预留。
```

### 关键交互

- 待办点击：审批 → OA 详情（新窗口或 iframe）；督办 → IM 对应话题 tab（复用 `topic-windows-p0.md` tab 机制）。
- 数字员工入口：头像列表（龙小督等），点击打开 IM 窗口；未读消息角标。
- 1.3.1 MVP 中通知/知识模块显示占位卡片 + 「1.4.0 上线」提示。
