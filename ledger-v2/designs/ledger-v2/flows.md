# 流程图：龙小督台账 V2

## 提交与打回主流程

```mermaid
flowchart TD
    A[下游处理节点] -->|填写并提交| B[保存不可变提交版本]
    B --> C[待直接上游提交]
    C -->|提交：认可并上报| D{是否督办人}
    D -->|否| E[保存上游新版本·保持已填报]
    E --> F[待更高一级提交]
    F --> C
    D -->|是| G[跟进状态已审核·节点督办人已审核]
    C -->|打回：原因必填| H[保存打回事件并引用最新版本]
    H --> I[退回实际直接下游]
    I --> J[龙小督通知 + 下游待办]
    J --> A
```

## 打回业务时序

```mermaid
sequenceDiagram
    participant U as 当前上游
    participant L as 督办台账
    participant D as 直接下游
    participant A as 龙小督
    U->>L: 选择打回并填写原因
    L->>L: 确认当前节点、操作角色和直接下游
    alt 事项已归档、撤回或节点已变化
        L-->>U: 停止打回并说明当前状态
    else 可以打回
        L->>L: 记录原因、轮次和被打回版本
        L->>D: 节点与待办退回直接下游
        L-->>U: 打回成功
        L->>A: 形成打回通知
        A-->>D: 告知原因、事项和原截止时间
    end
```

## 撤回流程

```mermaid
flowchart LR
    A[原督办人选择未归档记录] --> B[填写撤回原因]
    B --> C{权限、节点版本、未归档校验}
    C -->|失败| D[保持原状态]
    C -->|成功| E[记录已撤回]
    E --> F[锁定表单并清除待办]
    E --> G[通知协作者]
    E --> H[72 小时去重忽略该记录]
```

## 督办人终审与导出

```mermaid
flowchart TD
    A[批次有效记录] --> B{全部跟进状态属于\n已填报或已审核?}
    B -->|否| C[导出禁用并显示原因]
    B -->|是| D{督办人选择}
    D -->|逐项处理| E[修改/润色并提交]
    E --> F[该事项：已审核 + 督办人已审核]
    F --> B
    D -->|直接导出| G[导出即批次级认可]
    G --> H[文件生成成功]
    H --> I[全部有效记录：已归档 + 归档]
```

## 批次多选与导出

- 进入台账默认全选全部未归档批次；已归档批次默认不选中但可手动回看。
- 所选批次的全部事项形成统一事项合集；按逾期未填报、跟进中、已填报、已审核、已归档、已撤回排序，同一状态再按截止时间、批次序号、事项编号排序。
- 当前批次选择范围同时决定导出范围；任一选中批次失效或已归档，则阻止整个合并导出。
- 导出弹窗只确认所选批次数、总事项数、已撤回数和实际导出数，不再选择批次。
- 导出成功后归档所选批次的非撤回记录，已归档批次取消选择，并重新全选剩余未归档批次。
