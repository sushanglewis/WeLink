# 业务信息模型：龙小督台账 V2

> 本文只定义业务对象、业务信息和业务规则。

## 业务对象一：督办批次

督办批次是一组同时下发、共享同一填报截止时间并共同导出的事项填报记录集合。

| 业务信息 | 业务含义 | 业务规则 |
|---|---|---|
| 批次标识 | 系统原有的批次识别信息 | 展示名变化不改变历史关联关系 |
| 填报截止时间 | 本批事项要求完成反馈的时间 | 未提供时取正式下发后 36 小时，统一按 Asia/Shanghai 展示到分钟 |
| 批次展示名 | 用户在台账、通知和导出中看到的名称 | 格式为 `YYYY-MM-DD HH:mm-N`；所有批次都带序号，从 `-1` 开始 |
| 同截止序号 | 区分相同截止分钟的多个批次 | 按批次产生先后稳定分配，不因撤回或归档重排 |
| 总事项数 | 本批全部事项填报记录数 | 包含已撤回事项，界面同时单列已撤回数量 |
| 有效事项数 | 本批尚未撤回的事项填报记录数 | 为 0 时不可导出 |
| 可导出状态 | 本批是否满足导出条件 | 所有有效记录均为已填报或已审核时成立 |
| 批次归档状态 | 本批是否完成导出 | 导出成功即代表批次级认可并归档 |

## 业务对象二：事项填报记录

台账中“某批次下的某一个事项”就是一条独立的事项填报记录。同一事项可在不同批次中形成多条记录，因此撤回、提交和打回必须针对具体批次中的具体记录。

| 业务信息 | 业务含义 | 业务规则 |
|---|---|---|
| 所属批次 | 记录所在的督办批次 | 决定截止时间、批次名称和导出归属 |
| 事项编号 | 原督办事项的业务编号 | 用于判断 72 小时内是否重复督办 |
| 交办事项 | 标题级任务描述 | 卡片与详情均展示 |
| 交办内容 | 具体工作要求 | 详情只读展示，长文本可展开 |
| 事项跟进状态 | 记录在本轮跟进生命周期中的完成程度 | 固定五值，显示在卡片右上角 |
| 事项节点状态 | 当前由哪个角色处理或审核下游 | 固定八值，显示在卡片左下角 |
| 当前处理人 | 当前需要采取动作的人 | 决定待办归属和可操作权限 |
| 协作者责任链 | 本事项实际存在的督办人、经办人、转办人、次级转办人 | 不存在的转办层级显示「—」且不显示状态角标 |
| 当前有效提交角色 | 当前有效上报轮次中已经提交的角色集合 | 当前处理人显示黄色；集合内角色显示绿色勾；其余已存在角色显示灰色 |
| 曾被打回 | 本事项是否发生过任意一次打回 | 一旦为是，经办人和转办人后续均不可再次转办 |
| 最近一次提交 | 当前供上游审核的填报内容 | 每次重新提交形成新的历史版本 |
| 打回历史 | 历次打回人、接收人、原因、时间和轮次 | 全部进入流转记录，按时间倒序展示，不另设最新打回横幅 |
| 撤回标记 | 该记录是否被原督办人撤回 | 撤回后退出待办、导出和 72 小时限制判断 |

## 状态机一：事项跟进状态

事项跟进状态显示在事项卡右上角，固定为五个值：

| 状态 | 业务含义 | 进入条件 |
|---|---|---|
| 跟进中 | 本轮已下发，尚在填报或被打回修改 | 新建记录；或截止前被打回 |
| 已填报 | 已有协作者提交有效填报，等待后续角色处理 | 经办人、转办人或次转人提交 |
| 已审核 | 督办人已逐项修改或确认并提交 | 督办人对该事项点击提交 |
| 已归档 | 本轮跟进记录已经关闭 | 督办人成功导出所属批次 |
| 逾期未填报 | 已超过批次截止时间，当前仍需补充或重填 | 截止后尚未有效提交；或截止后被打回 |

原「推进中」统一更名为「跟进中」。

## 状态机二：事项节点状态

事项节点状态显示在事项卡左下角，固定为八个值：

1. 待经办人处理
2. 待转办人处理
3. 待次转人处理
4. 待转办人提交
5. 待经办人提交
6. 待督办人提交
7. 督办人已审核
8. 归档

业务含义：前三个状态表示由该角色填报或转办；中间三个状态表示该角色正在查看直接下游提交，可选择提交或打回；「督办人已审核」表示督办人已逐项提交；「归档」表示批次已导出关闭。

## 协作者当前轮次状态

- 黄色圆点：当前处理人。
- 绿色圆形白勾：该角色在当前有效上报轮次中已提交。
- 灰色圆点：本轮尚未提交，或其先前提交已因打回失效。
- 提交时，当前角色加入有效提交集合并将待办交给直接上游。
- 打回时，被打回的直接下游移出有效提交集合并变为黄色；更下游的有效提交保持绿色。
- 历史提交和失效原因保留在填报版本与流转记录，不通过永久绿色勾表达。

## 独立业务标记：已撤回

「已撤回」不加入上述两套状态机。撤回后：

- 台账对该记录右上优先显示「已撤回」，卡片左下显示「督办人已撤回」。
- 保留撤回前的跟进状态和节点状态，便于还原历史。
- 清除当前待办归属，锁定填报操作。
- 不参加批次导出，也不再触发 72 小时重复督办限制。

## 业务对象三：填报版本

每次点击提交都形成一份不可覆盖的填报版本，业务上需要记录：

- 对应的事项填报记录；
- 第几次提交；
- 提交人及其当时角色；
- 提交时的五要素完整内容；
- 是否基于上一位协作者的内容修改；
- 提交时间。

上游修改后提交，代表其认可修改后的版本并对继续上报负责。

## 业务对象四：打回记录

每次打回都形成一条独立业务记录，包含：

- 被打回的事项填报记录和填报版本；
- 打回人及其角色；
- 实际接收打回的直接下游及其角色；
- 打回原因；
- 打回前后节点；
- 第几次打回；
- 打回时间。

打回记录不可被后续提交覆盖。下游可以重新提交；经办人或转办人如果已有直接下游，也可以继续向下打回并形成新的打回记录。事项发生过打回后，经办人和转办人均不可新增或更换转办关系。

## 业务对象五：流转记录

流转记录默认展开，并按时间汇总展示以下动作：

- 下发、转办、再转；
- 各角色提交；
- 打回；
- 撤回；
- 督办人逐项审核；
- 批次导出归档。

每条记录至少说明谁、以什么角色、在什么时间执行了什么动作，以及事项从哪个节点流转到哪个节点。
每次打回必须单独显示轮次、打回人和完整原因；后续提交或再次打回不得覆盖历史原因。

## 业务对象六：当前台账批次范围

- 当前台账范围由用户选中的一个或多个批次组成。
- 进入台账时默认全选全部未归档批次；已归档批次默认不选中但可手动选择查看。
- 当前批次范围同时决定事项卡展示范围和 Excel 导出范围。
- 任一选中批次不可导出时，整体不可导出；不自动忽略或部分导出。
- 事项排序先看跟进状态：逾期未填报、跟进中、已填报、已审核、已归档、已撤回；同一状态再按截止时间、批次序号和事项编号排序。

## 关键业务关系

- 一个督办批次包含多条事项填报记录。
- 同一事项编号可以在多个批次中形成不同填报记录。
- 一条事项填报记录可以产生多次提交版本和多次打回记录。
- 一条事项填报记录在任一时刻只有一个当前处理人。

## 导出业务规则

- 同一批次可以同时包含「已填报」和「已审核」记录。
- 只要所有有效记录均属于这两个状态，督办人即可导出，不要求逐项审核。
- 导出成功代表督办人认可整批内容：所有有效记录的事项跟进状态变为「已归档」，事项节点状态变为「归档」，相关待办关闭。
- 已撤回记录保持撤回，不进入导出结果。
- 总事项数包含已撤回记录；导出确认需同时说明总事项数、已撤回数和实际导出数。
- 导出成功后所选批次自动取消选择，并重新全选剩余未归档批次。
