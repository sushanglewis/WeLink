# UI 规格：龙小督台账 V2

## 设计基线

- 最终方向：A「原位增补」，确认记录见 `ledger-v2/direction-approved.md`。
- 主基线截图：`.context/attachments/Eu03Jv/展开督办台账-已提交督办状态.png`。
- 必须保持现有功能栏、会话列表、单列台账、批次选择、横向事项卡、事项详情、协作者和纵向表单的信息层级。

## 文档交付框架

- `index.html` 使用仓库既有 Lincoln 门户：左侧页面索引、中间 Mac 窗口 iframe、右侧页面说明。
- 门户默认打开 HTML PRD，并提供状态机业务说明与交互原型入口。
- 交互原型位于 `pages/prototype/01-supervisor.html`；门户左侧目录分别提供督办人、经办人、转办人、次级转办人视角入口，产品界面内部不出现角色切换。

## 页面结构

1. 左侧功能栏：保持现有布局。
2. 会话列表：龙小督行继续展示普通未读数和待办数。
3. 台账标题栏：保持现有标题和收起入口。
4. 批次区：「跟进批次」下拉框支持多选；导出按钮保持右侧，并展示当前选择的导出资格提示。
5. 事项卡区：保持横向卡片和分页；右上显示事项跟进状态，左下显示事项节点状态。
6. 详情区：交办事项下增加交办内容，再展示协作者和填报表单。
7. 流转记录：放在表单底部，默认展开，完整呈现历次提交、打回、撤回和归档。
8. 固定操作区：沿用现有底部区域，根据角色和节点显示撤回、打回、转办、暂存或提交。

## 主要流程

### 批次多选与事项合集

- 取消「按批次 / 平铺模式」切换，批次选择框直接支持多选。
- 进入台账默认选中全部未归档批次；已归档批次默认不选中但可手动查看。
- 下拉列表提供「全选未归档」「仅选可导出」「清空」。
- 每个批次展示「共 N 项 · 已撤回 N 项 · 已填报 N 项 · 已审核 N 项 · 已归档 N 项 · 待处理 N 项」和导出结论。
- 下方展示所选批次的事项合集，每张卡增加所属批次。
- 排序依次为逾期未填报、跟进中、已填报、已审核、已归档、已撤回；同一状态按截止时间、批次序号、事项编号排序。
- 事项卡只使用一行横向轨道，支持鼠标/触控拖动和左右按钮切换。

### 提交

- 当前处理人完成必填项后提交。
- 下游提交后，上游收到待办并看到最新内容。
- 上游提交表示认可并继续上报。
- 督办人提交后，事项跟进状态变为已审核，事项节点状态变为督办人已审核。

### 打回

- 在待上游提交节点展示；收到上游打回后，如当前角色仍有直接下游，也继续展示。
- 弹窗说明事项、提交人、退回对象和原截止时间；原因必填。
- 成功后原内容保留，下游待办增加；不显示独立红色打回横幅。
- 每次打回均向默认展开的流转记录追加轮次、打回人和完整原因，历史多次打回不得覆盖。
- 事项一旦发生过打回，经办人和转办人后续不再显示转办入口；若已有直接下游，仍可继续逐级打回。

### 协作者状态

- 头像右下使用统一 14px 圆形角标：黄色表示当前待处理，绿色白勾表示当前有效轮次已提交，灰色表示尚未提交或提交已失效。
- 打回只使被打回的直接下游退出有效提交集合，更下游的绿色提交保持不变。
- 不存在的角色显示「—」且不显示状态角标；历史提交由流转记录承载。

### 撤回

- 仅原督办人、归档前可操作；已审核的记录不可撤回。
- 弹窗说明对待办、72 小时规则和导出的影响；原因必填。
- 成功后卡片右上显示已撤回、左下显示督办人已撤回，表单只读。

### 多批次导出

- 当前选中的批次就是导出范围；至少选择一个批次才能导出。
- 任一选中批次含跟进中/逾期未填报有效事项或已经归档时，整体禁止导出并说明原因。
- 导出弹窗只确认批次数、总事项数、已撤回数、实际导出数和归档影响，不再选择批次。
- 导出成功后，所选批次非撤回记录全部显示已归档/归档，批次自动取消选择，并重新全选剩余未归档批次。

## 角色与操作状态

- 督办人：可逐项修改、打回、提交、撤回和导出。
- 经办人：未发生打回时可填报或转办；收到督办人打回后不可再次转办，可继续打回既有转办人或提交。
- 转办人：未发生打回时可填报或再转；收到经办人打回后不可再次转办，可继续打回既有次级转办人或提交。
- 次级转办人：可填报和重新处理打回内容，只能向转办人提交。
- 非当前处理人：只读，不展示可执行主按钮。

## 页面状态

- 空批次：显示「本批暂无督办事项」。
- 未选择批次：事项区显示「请选择批次」；无未归档批次时提示可从列表查看历史记录。
- 长交办内容：默认三行，提供展开/收起。
- 已撤回或已归档：表单只读，操作按钮不可用。
- 状态已变化：停止当前弹窗操作并提示重新确认事项状态。
- 导出不满足条件：按钮禁用，旁边明确展示阻塞批次数；批次列表逐项显示待处理数和导出结论。

## 原型验收

- 可多选批次并保持现有信息框架；产品界面不出现视图或角色切换控件。
- 督办人、经办人继续向下打回、转办人继续向下打回、次级转办人重新提交分别通过四个独立场景链接演示；经办人和转办人入口直接打开向实际下游打回的确认界面。
- 四个角色视角均显示同一套协作者黄、绿、灰三态；所有已打回场景均不显示转办按钮。
- 可选择批次范围和事项、展开交办内容、提交、打回、撤回和多批次导出。
- 所有动作同步更新卡片状态、详情状态、待办计数和流转记录。
- 不出现评论、评论数、未读协作消息或手动刷新。
