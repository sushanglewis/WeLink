# 用户故事：龙小督台账 V2

## US-01 查看交办内容

- 作为经办人或转办协作者，我希望在填报详情直接看到完整交办内容，以便无需回到聊天记录寻找工作要求。
- 验收：字段只读；三行折叠；全部四类角色可见；空值明确提示。

## US-02 撤回误下发事项

- 作为原发起督办人，我希望在归档前撤回错误事项，以便终止下游待办并立即重新下发正确记录。
- 验收：原因必填；按批次记录精确撤回；下游锁定并收到通知；撤回记录不阻塞导出和 72 小时去重。

## US-03 识别批次

- 作为台账用户，我希望从批次名直接看到截止时间，以便快速判断优先级并区分同截止时间批次。
- 验收：格式、默认 +36 小时、稳定序号和历史迁移符合需求文档。

## US-04 合并导出

- 作为督办人，我希望当前选择的多个批次就是事项查看和 Excel 导出范围，以便在同一台账现场处理阻塞事项并避免人工合表。
- 验收：任一选中批次不合格则整体禁止导出；已撤回项计入总数但排除导出；确认弹窗不再选择批次；导出后统一归档并自动重选剩余未归档批次。

## US-05 统一查看跨批次事项

- 作为多角色用户，我希望默认选中全部未归档批次并看到事项合集，以便无需切换视图即可同时掌握逾期、跟进、已填报和已审核事项。
- 验收：批次支持多选及三个快捷操作；事项先按状态优先级、再按截止时间稳定排序；卡片标明所属批次；已归档批次可手动选择回看。

## US-06 逐级打回

- 作为督办人、经办人或转办人，我希望将直接下游的不合格提交打回并说明原因，以便下游在保留原文的基础上修改后重新上报。
- 验收：
  - Given 当前节点为 `待经办人提交`，When 经办人填写原因并打回，Then 节点回到实际转办人处理，转办人待办 +1。
  - Given 当前节点为 `待督办人提交` 且无转办人，When 督办人打回，Then 节点回到经办人处理。
  - Given 经办人收到督办人打回且该事项存在转办人，When 经办人继续打回，Then 节点回到转办人处理。
  - Given 转办人收到经办人打回且该事项存在次转人，When 转办人继续打回，Then 节点回到次转人处理。
  - Given 事项跟进状态为已填报，When 任一级打回，Then 事项跟进状态变为已退回；任一下游协作者重新提交后回到已填报；超过填报截止时间仍未重新提交转逾期未填报。
  - Given 下游重新提交，When 上游选择提交，Then 系统保存新版本并直接向更高一级上报。
  - Given 记录已归档、已撤回或当前处理节点已经变化，When 用户提交打回，Then 系统拒绝且保持原业务状态。

## US-07 查看流转历史

- 作为任一相关协作者，我希望查看每次提交和打回的时间、人员、原因及版本，以便理解当前内容从何而来。
- 验收：普通协作者只读；历史版本不可覆盖；最新打回提示与流转记录一致。

## US-08 督办人终审批次

- 作为督办人，我希望既能逐项润色并提交，也能直接导出已经填报完成的批次，以便根据批次规模选择合适的终审效率。
- 验收：
  - Given 事项处于待督办人提交，When 督办人修改并提交，Then 跟进状态为已审核、节点状态为督办人已审核。
  - Given 批次所有有效事项均为已填报或已审核，When 督办人直接导出，Then 无需逐项提交，导出后有效记录全部归档。
  - Given 批次存在跟进中或逾期未填报记录，When 督办人尝试导出，Then 系统阻止并说明原因。
