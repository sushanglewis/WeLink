# 龙小督台账 V2 · 三方向共同设计 Spec

## 产品与目标

龙小督是嵌入 EAIC 会话的督办数字员工，右侧台账用于督办人、经办人、转办人和次转人查看同一批次中的事项填报记录并逐级协作。本轮原型不是重新设计整套 EAIC，而是用一个 1600×1000 的桌面交互沙盘验证六项迭代：交办内容展示、督办人撤回、截止时间批次命名、多批次合并导出、平铺模式和逐级打回。三版必须使用相同的业务内容、状态和品牌色，差异落在信息架构、操作节奏和流程可见性，不能只换配色。

## 目标受众与使用场景

主要评审人是产品经理、业务负责人和研发团队。实际用户会在一米左右的桌面屏幕距离处理高密度信息：经办人需要查看跨批次的全部相关事项，督办人同时关注批次整体完成度、逐项内容质量和导出归档。产品界面不提供角色切换；督办人、经办人和转办人的原型通过独立场景链接演示。典型演示从督办人视角开始：批次 `2026-10-24 12:00-2` 包含已填报、已审核、跟进中和已撤回记录；督办人可打回已填报项、逐项提交为已审核，或在全部有效记录均为已填报/已审核时直接导出归档。平铺模式展示全部相关事项，但不显示导出入口。

## 必含内容与交互

1. 顶部或主要导航中提供「平铺模式 / 按批次查看」切换，并显示当前角色待办数。
2. 批次展示名使用截止日期时间与稳定序号；批次摘要区显示有效事项、已填报、已审核和不可导出原因。
3. 事项卡右上角展示事项跟进状态，左下角展示事项节点状态；不得混淆。
4. 详情区先展示交办事项，再展示只读交办内容；长文本三行折叠并可展开。
5. 当前项必须呈现协作者责任链、最新填报五要素、预计完成时间和进度评价。
6. 上游操作区并列显示「打回」「提交」；打回弹窗包含直接下游、内容摘要、原截止时间和必填原因。
7. 督办人撤回弹窗原因必填，并解释撤回对待办、72 小时规则和导出的影响。
8. 多批次导出面板支持勾选、禁用不可导出批次并说明原因；明确“导出即认可并归档”。
9. 详情中提供业务流转记录，展示提交、打回、撤回和导出，不展示技术日志。

## 共同演示数据

- 批次：`2026-10-24 12:00-2`，4 条记录。
- `SJ202610140932`：已填报；待督办人提交；经办人任伊娴提交。
- `A0002`：已审核；督办人已审核。
- `A0003`：跟进中；待经办人处理。
- `A0004`：已撤回；不参与导出。
- 交办事项：研究龙岗存量数据治理和价值挖掘合作方案。
- 交办内容：会同区政务和数据局梳理数据资源现状，形成合作需求清单、可落地场景与下一步推进计划。

## 情感基调与视觉母题

基调是冷静、可信、行动优先。视觉母题是「一条记录沿责任链向上流转，打回时沿原路径返回」，但它只能通过现有事项卡、协作者、操作栏和折叠流转记录表达，不能据此新增侧栏或重构页面。母题来自逐级协作本身，而不是抽象科技图形。

## 输出与约束

- 每个方向一个独立、可直接打开的纯 HTML 文件，固定评审视口 1600×1000。
- 正文不小于 14px，辅助标签不小于 12px，文本对比度达到可读标准。
- 不使用外部图片；工具型界面中的图片不是内容必需，头像使用文字首字占位。
- 页面允许轻量 JavaScript 演示视图切换、展开、弹窗和选中项，但不连接真实系统。
- 三版必须共享同一现有信息设计框架：左侧功能栏、会话列表、单列台账、批次选择与导出、横向事项卡、事项详情、协作者、纵向表单。只允许比较新增控件的落位与提示强度。
- 三版完成后统一截图并展示；用户选定前不生成最终 `index.html`。

## 三方向逻辑

- 方向 A · 原位增补：新增能力全部放入与其业务最接近的现有区块，视觉变化最小。
- 方向 B · 紧凑操作：信息层级不变，将视图切换放到标题栏并压缩新增控件占用。
- 方向 C · 状态提示：信息层级不变，在批次区增加轻量状态说明与导出资格提示。
