# 事项看板 · 产品需求文档（dashboard v1.2）

## 一、背景与数据来源

本章讲什么：这个页面为谁做、数据从哪来、本期做到什么程度。

- **业务背景**：AI+重点工作推进系统的 GUI Dashboard「事项看板」，面向领导层与督办人，一屏掌握全部督办事项的进展与风险。
- **来源数据**：生产环境导出的两张维格表——《督办任务》主表（40 个字段，含事项状态、截止时间、办结状态等）与《跟进记录》表（23 个字段，含进度评价、开始日期、督办批次号等）。
- **上游定版包**：`im-agent-supervision-teable-v1`。本包是其 dashboard 部分的独立分化，原包保持定版不动。
- **本期范围**：只做看板（指标卡 + 明细列表 + 下钻抽屉），不做填报、不做权限控制。

### 版本演变（v1.1 → v1.2）

- 指标卡由 5 张调整为 7 张：保留事项总数 / 正常 / 风险 / 逾期，新增按进度评价的推进中 / 已落实 / 已滞后 3 张；不设「完结」卡，完结由「办结状态」字段表达。
- 取数原则修订（上游包决策 D-43，取数原则）：指标卡允许引用跟进记录表，但仅限「按任务编号去重、只取每个事项最新一条跟进记录」的口径。
- 明细列表由 15 列扩展为 25 列；指标卡始终按全部事项全量计算，不随筛选与分页变化（对应上游验收项 GUI-08，指标卡按筛选后全量计算、与分页无关）。

## 二、页面指标（7 张卡）

本章讲什么：页面顶部 7 张指标卡各自回答什么问题、数字怎么算出来，以及两组「核对关系」为什么恒成立。

**三条共同规则（适用于全部 7 张卡）：**

- 仅展示，不可点击，无交互下钻。
- 不受下方筛选条件影响：无论怎么筛选，指标卡始终按全部事项全量统计。
- 与分页无关：翻页不改变任何一张卡的数值。

风险 / 逾期两张卡的颜色与明细列表行首的黄 / 红色条一一对应（黄 = 风险，红 = 逾期）。

### 1. 事项总数（M1）

- **这句话是什么意思**：当前纳入督办的事项总量。本期无权限控制，即为领导层 / 督办人的最大权限视角。
- **怎么算**：直接统计《督办任务》主表的全部记录数。
- **技术口径**：`count(全部记录)`。

### 2. 正常（M2）

- **这句话是什么意思**：既未进入「临期」警戒、也未逾期的事项数。
- **怎么算**：主表「事项状态」字段值为「正常」的记录数。事项状态只有三个值（正常 / 风险 / 逾期），由后台每天定时判定，判定规则见「风险」「逾期」两卡。

### 3. 风险（M3，黄色卡片）

- **这句话是什么意思**：距离完成时限不足 7 天、但尚未完结的事项数——提示「要抓紧了」。只与时间有关，与有没有填报跟进无关。
- **怎么算**：后台服务每天定时重新计算（上游状态机规则 T7，风险判定：进入截止前 7 天且未完结记为风险）：今天已到达「完成时限前 7 天」这个节点、且事项未完结，即记为风险。
- **技术口径**：`count(事项状态 == "风险")`。

### 4. 逾期（M4，红色卡片）

- **这句话是什么意思**：超过了完成时限、且仍未完结的事项数。逾期以任务的完成时限为准，不按督办反馈的截止时间算。
- **怎么算**：后台服务每天定时重新计算（上游状态机规则 T8，逾期判定：超过完成时限且未完结记为逾期）：今天晚于完成时限、且事项未完结，即记为逾期。
- **技术口径**：`count(事项状态 == "逾期")`。

### 5. 推进中（M5，蓝色卡片）

- **这句话是什么意思**：最新一次跟进评价为「推进中」的事项数——即工作仍在正常推进、尚未落实完成也未明显滞后的事项。
- **怎么算**：在《跟进记录》表按任务编号分组，每个事项只取创建时间最新的一条跟进记录（若同一事项有两条跟进记录创建时间完全相同，以督办批次号更大——即更晚一批督办的——那条为准；历史批次不参与）。这条记录的「进度评价」为「推进中」则计数，一个事项只计一次。
- **数据前提**：新导入的事项会自动生成一条进度评价为「推进中」的跟进记录（见第六章），因此每个事项必有最新进度评价，推进中 / 已落实 / 已滞后三张卡之和必然等于事项总数。
- **技术口径**：跟进记录表按任务编号分组取最新一条，`进度评价 == "推进中"` 则计数。

### 6. 已落实（M6，绿色卡片）

- **这句话是什么意思**：最新一次跟进评价为「已落实」的事项数——即责任单位反馈工作已按要求落实到位的事项。
- **怎么算**：取数逻辑与「推进中」完全相同（按任务编号去重、只取最新一条、历史批次不参与、新导入默认推进中），只是判定值换成「已落实」。

### 7. 已滞后（M7，琥珀色卡片）

- **这句话是什么意思**：最新一次跟进评价为「已滞后」的事项数——即经督办人评价进度明显落后、需要重点关注催办的事项。
- **怎么算**：取数逻辑与「推进中」完全相同，只是判定值换成「已滞后」。

### 核对关系（两组恒等式，为什么恒成立）

- **事项总数 = 正常 + 风险 + 逾期**。原因：事项状态只有三个值；「完结」不是事项状态，由独立的「办结状态」字段（已办结 / 未办结）表达，已办结的事项仍持有正常 / 风险 / 逾期三者之一。
- **事项总数 = 推进中 + 已落实 + 已滞后**。原因：每个事项必有跟进记录、必有最新进度评价（第六章初始化规则保证）。

## 三、数据明细列表（25 列）

本章讲什么：列表每一列给人看什么、数据取自哪张表的哪个字段、点表头排序时按什么规则排。

**通用交互：**

- 序号按当前排序结果连续编号，序号本身不参与排序。
- 长文本列省略显示，鼠标悬浮提示全文。
- 默认排序：按「交办时间」由近及远（降序）；点击表头可切换排序列与升 / 降序。
- 分页：默认 20 条 / 页，可切换 10 / 20 / 30 / 50 条 / 页；翻页不改变指标卡数值。
- 排序方式说明：日期列按时间先后排；文本列按文字顺序排；有业务约定的列按业务约定顺序排（事项状态：正常 → 风险 → 逾期；进度评价：推进中 → 已落实 → 已滞后）。

## 五、下钻抽屉（点击行打开）

本章讲什么：点开一条事项，抽屉里展示什么。

- **事项详情字段**：任务编号、责任单位、经办人（含电话）、交办时间、完成时限、督办频率、事项类别、领导批示。只展示经办人，不展示转办人 / 次级转办人。
- **跟进记录列表**：按创建时间由近及远倒序展示，标题显示条数。
- **每条跟进记录卡片**：
  - 首行（右对齐）：跟进状态（推进中 / 已填报 / 逾期未填报 / 归档）+ 当前节点（如「待督办人提交」）+ 跟进日期。
  - 次行：四个角色——督办人 / 经办人 / 转办人 / 次级转办人（空值显示「—」）。
  - 下方固定五要素：进度评价、预计完成时间、落实情况、存在困难、下一步计划。其中落实情况、存在困难、下一步计划允许为空，空值统一显示「—」（列表与下钻一致）。
  - 不展示填报人、角色徽章、批次编号。

## 六、跟进记录初始化规则

本章讲什么：为什么每个事项都一定有跟进记录，老系统导入的数据和新产生的事项分别怎么处理。

1. **每个事项必有跟进记录**：不存在没有跟进记录的事项——这是「推进中 + 已落实 + 已滞后 = 总数」恒等式成立的数据前提。
2. **历史数据导入**：按导入数据为每个事项初始化一条「事项跟进状态 = 归档」的跟进记录，进度评价取导入值。
3. **新导入事项**：进度评价若为空，默认给「推进中」。
4. **三项反馈内容可空**：落实情况、存在困难、下一步计划允许为空，空值统一显示「—」。

## 七、权限说明

- 本期**不做权限控制**：页面为领导层 / 督办人最大权限视角，所有能看到页面的人看到的内容完全一致（7 张卡按全量计算，无身份过滤）。
- 经办人、转办人、次级转办人的角色视角后续版本再立项。

## 八、验收标准

- **手算核对**：原型 TODAY = 2026-09-08，Mock 11 条，逐条最新跟进记录进度评价：推进中 6 / 已落实 2 / 已滞后 3。全量视角（唯一视角，无权限控制）：总数 11 / 正常 9 / 风险 1 / 逾期 1 / 推进中 6 / 已落实 2 / 已滞后 3，与原型展示一致。
- **核对**：9 + 1 + 1 = 11（事项状态三值）✓；6 + 2 + 3 = 11（最新跟进记录进度评价）✓。
- 风险 / 逾期为纯时间口径，与是否填报无关：已填报但临期 / 超期的事项照常计入风险 / 逾期。
