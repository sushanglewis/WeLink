# PRD：龙小督台账 V2

> 版本：v2.3-review · 状态：approved · 与门户 PRD 页（pages/docs/prd.html）同口径。

> 本文是本次迭代的业务唯一口径，只说明用户、场景、状态、规则和验收标准，不规定技术实现方案。

## 产品背景

龙小督台账用于督办人、经办人、转办人和次转人在同一条事项填报记录上逐级协作。现有系统已按「批次 → 事项卡 → 事项详情」组织内容，本次迭代保持该信息设计框架。

## 产品目标

1. 经办人无需返回聊天记录即可理解完整交办内容。
2. 督办人可撤回错误下发记录，并立即重新发起督办。
3. 用户可直接从批次名称识别截止时间和同截止时间下的批次顺序。
4. 督办人可一次合并导出多个合格批次。
5. 经办人打开台账即可看到全部待办事项合集，无需逐批查找。
6. 上游可将不合格填报逐级打回直接下游修改。
7. 督办人可为批次设置自定义别名，其他协作者可见，且用于导出文件命名。
8. 填报内容按用户-批次-事项编号自动保存，不丢失草稿。

## 用户与责任链

- **督办人**：发起督办、查看和修改下游填报、逐项审核、撤回事项、导出归档。
- **经办人**：直接填报或转办；审核转办人的填报；收到打回后可继续打回转办人。
- **转办人**：直接填报或再转；审核次转人的填报；收到打回后可继续打回次转人。
- **次转人**：责任链末端，只负责填报或重新处理打回内容。

## 功能需求

### 1. 交办内容

- 事项详情在交办事项下展示只读「交办内容」，内容与下发原文一致。
- 超过三行时默认收起，可展开/收起；空值显示「暂无交办内容」。
- 督办人、经办人、转办人、次转人均可见。

### 2. 督办人撤回

- 仅原发起督办人可在归档前撤回某批次下的具体事项填报记录（按事项编号判定）。
- 撤回原因必填；成功后移除下游待办、锁定表单并通知全部受影响下游协作者。
- 已撤回记录为终态，不参加导出，也不再触发「72 小时内不重复督办同一事项」限制，同一事项可立即重新发起。

### 3. 批次命名

- 批次名称统一为 `YYYY-MM-DD HH:mm-N`，格式示例：`2026-10-24 12:00-1`。
- 所有批次均带自增序号，从 `-1` 开始；同截止分钟依次为 `-1`、`-2`、`-3`。
- 未提供截止时间时，默认取正式下发后 36 小时。
- 历史批次先补齐截止时间，再按相同规则统一重命名。

### 4. 多批次合并导出

- 批次选择框支持多选，勾选多个批次一次性合并导出为同一个 Excel 文件。
- 当前批次选择同时决定事项卡合集和导出范围。
- 用户进入台账时默认全选全部未归档批次；已归档批次默认不选中，但可手动选择查看。
- 提供「全选未归档」「仅选可导出」「清空」快捷操作。
- 批次内所有有效记录均为「已填报」「已审核」或「已归档」时可导出；已归档批次可再次导出，已归档记录仅重新导出、不重复归档。
- 任一选中批次不满足条件时，整体禁止导出；不自动忽略或部分导出。
- 每个批次列表项展示全部状态的事项数：总数、跟进中、已退回、已填报、已审核、已归档、逾期未填报、已撤回、需处理。
- 各状态事项数之和与总数对齐：总数 = 跟进中 + 已退回 + 已填报 + 已审核 + 已归档 + 逾期未填报 + 已撤回。
- 需处理 = 跟进中 + 已退回 + 已填报 + 逾期未填报，即所有仍待下游或督办人处理的记录。
- 导出弹窗只确认范围和归档影响，不再选择批次。
- 导出即代表督办人认可该批内容；成功后有效记录统一变为「已归档 / 归档」。
- 导出成功后，已归档批次自动取消选择，并重新全选剩余未归档批次。

### 5. 统一台账视图

- 台账面板以统一视图展示所选批次的全部事项（含撤回记录），不再按批次层级收纳。
- 经办人打开面板即进入该视图：默认全选全部未归档批次，直接看到当前需要跟进的跨批次事项合集。
- 排序顺序：逾期未填报 > 跟进中 > 已退回 > 已填报 > 已审核 > 已归档 > 已撤回。
- 同一状态内按填报截止时间升序，再按批次创建时间和事项编号排序。
- 所有事项卡单行横向排列，可左右拖动，也可用左右按钮逐项切换。
- 所有事项卡左上角显示截止时间（「截止 YYYY-MM-DD HH:mm」），不显示所属批次，避免非督办角色误解。

### 6. 逐级打回

- 督办人、经办人、转办人均需对直接下游的填报质量负责，可在待提交节点执行「打回」。
- 提交即表示认可当前内容并向上流转，不增加独立「通过」步骤。
- 打回对象为实际直接下游，原因必填，原截止时间不变。
- 收到打回的经办人若仍有转办人，可继续打回转办人；转办人若仍有次转人，可继续打回次转人。
- 每一级打回都单独记录原因、操作人、接收人、时间和轮次。
- 原填报内容保留供修改，每次重新提交形成新的历史版本。

### 7. 批次别名

- 督办人可为批次设置自定义别名并保存；别名仅用于展示和导出命名，不修改批次编号。
- 经办人、转办人、次转人均可看到督办人定义的批次别名。
- 别名不参与下拉列表选项排序，批次选项仍按截止时间排序。
- 合并导出时，若所选范围中最新的一条批次存在别名，导出文件以该别名命名；无别名时使用默认命名。

### 8. 填报自动保存与主动保存

- 用户打开台账看板即开始自动保存：每 3 秒保存一次当前填报表单内容。
- 用户可点击「保存」按钮，主动保存当前批次-事项的填报内容。
- 保存内容按「用户-批次-事项编号」存储到后台数据库；切换事项、刷新或重开看板后自动恢复，填报内容不丢失。
- 自动保存与主动保存仅保存填报草稿，不改变事项状态与流转记录；正式提交仍以「提交」操作为准。

## 两套状态机

### 事项跟进状态（卡片右上角）

`跟进中 / 已退回 / 已填报 / 已审核 / 已归档 / 逾期未填报 / 已撤回`

- 下游有效提交后为已填报。
- 督办人逐项提交后为已审核。
- 批次导出成功后为已归档。
- 打回后为已退回；超过填报截止时间仍未重新提交转逾期未填报。
- 督办人归档前撤回后为已撤回，终态；不参与导出与待办。

### 事项节点状态（卡片左下角）

`待经办人处理 / 待转办人处理 / 待次级转办人处理 / 待转办人提交 / 待经办人提交 / 待督办人审核 / 督办人已审核 / 归档 / 已撤回`

- 已撤回为督办人撤回后的节点终态，卡片左下显示「督办人已撤回」，撤回前节点保留供回看。

## 通知与待办

- 下游提交：仅通知直接上游，并将待办归属转移给上游。
- 打回：通知本次接收打回的直接下游并转移待办。
- 督办人撤回：通知全部受影响的下游协作者并移除待办。
- 通知由龙小督发送，包含事项编号、动作人、原因（适用时）、原截止时间和台账入口；具体文案见《通知文案剧本》。

## 明确不做

- 不设计记录评论、评论数量或协作未读徽标。
- 不增加手动刷新功能。
- 不在产品界面内提供角色切换；不同角色通过独立原型场景评审。
- 不改变现有功能栏、会话列表、台账纵向结构、横向事项卡和表单结构。

## 验收标准

- [ ] 六项功能可在同一原型中完整演示。
- [ ] 批次多选默认全选未归档批次，事项合集排序正确，卡片保持单行可拖动切换。
- [ ] 经办人和转办人收到打回后，可在仍有下游时继续向下打回。
- [ ] 任一选中批次不满足条件时整体禁止导出；导出确认不再选择批次。
- [ ] 所有批次名均使用 `-N`，首批也显示 `-1`。
- [ ] 三个待提交节点名称不包含额外括号文案。
- [ ] 页面不存在产品内角色切换和右上角漂移状态。
- [ ] 督办人可设置并保存批次别名，其他角色可见，别名不影响批次排序。
- [ ] 合并导出文件名取所选最新批次的别名；无别名时使用默认命名。
- [ ] 打开看板后每 3 秒自动保存当前表单，点击「保存」立即保存，按用户-批次-事项编号存储并可恢复。
